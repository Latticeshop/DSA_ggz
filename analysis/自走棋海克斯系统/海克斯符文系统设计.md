# 海克斯符文系统设计方案（Hextech Rune System）

> 红警3日冕自走棋（DSA）自定义玩法设计文档
> 参考原型：英雄联盟「斗魂竞技场 / 海克斯大乱斗」三选一强化符文（Augment）肉鸽事件
> 状态：设计定稿；模式配置、真实候选抽取、首批符文效果、事件 UI 与真实数据面板已实现，剩余符文与正式素材待继续开发

> 实现基准：以 `E:\Ra3_AutoChess\DSA_ggz` 当前代码为准。本文同时记录已实现现状与后续目标；标记为“待实现”的内容不得视为现有功能。

## 1. 背景与目标

借鉴英雄联盟斗魂竞技场的**三选一强化符文**肉鸽机制：每隔若干回合，每位玩家独立看到 3 个随机符文，选择 1 个获得，效果可持续整局、可叠加成长。本方案将该机制本地化到红警3日冕自走棋，形成全新的「海克斯符文」模式。

**核心目标：**

- 每名玩家在特定回合弹出**三选一**符文对话框，独立选择、互不影响
- 符文效果全部使用本图已有系统实现（AttributeModifier 增益、发钱、召唤等）
- 作为**新模式开关**接入现有游戏模式选择流程，房主可选开/关
- 符文池本地化设计，覆盖进攻 / 防御 / 经济 / 召唤 / 功能五大类

## 2. 核心机制总览（目标正式流程）

> 本节描述最终玩法目标。当前代码已经按“先判定全场稀有度 → 每名玩家独立筛池 → 无放回抽取 3 个不同符文”运行，并接入首批可实测符文；完整符文数量与专属图标仍待补齐，实际进度见第 6 章。

```
回合开始
  └─ RoundLuaManager._begin() 触发 HextechRune:OnRoundBegin(lvc)
       ├─ 模式开关已开启（房主选择 或 开启了随机箱子）？
       │    └─ 当前回合 ∈ 发放回合表（5/11/18，按次数 N 截取）？
       │         └─ 对每个存活玩家：
       │              ├─ 按稀有度概率抽 3 个符文（去重 + 每人独占 + 兵种标签）
       │              └─ 弹出三选一对话框（选项含兵种标签）
       └─ 玩家点击选择
            ├─ 记录符文 + 兵种到 PlayerOwnedRunes[playerIndex] / PlayerOwnedRuneIds[playerIndex]
            └─ 登记到回合回调 → 每回合出兵时按兵种对己方单位施加 buff
                 └─ 公共面板广播「玩家X获得了符文Y」
```

## 3. 触发时机（已确认）

本图科技自动解锁节奏（用户确认 + 脚本佐证）：

| 科技阶段 | 自动解锁回合 | 脚本触发条件（lvc） | 符文事件回合（解锁前一回合） |
| -------- | ------------ | ------------------- | ---------------------------- |
| T2（二本） | 第 6 回合 | NATURALUNLOCK__1：lvc ∈ [4,5] | **第 5 回合** |
| T3（三本） | 第 12 回合 | NATURALUNLOCK__2：lvc ∈ [4,11] | **第 11 回合** |
| T4（四本） | 第 19 回合 | NATURALUNLOCK__3：lvc ∈ [4,18] | **第 18 回合** |

- 每名玩家整局共经历 **N 次**三选一。入局前未勾选「开启随机箱子」时默认不启用；勾选时默认 3 次。房主仍可在模式菜单中手动改为 0/1/2/3 次
- 事件在**备战阶段**弹出（RoundLuaManager 回合开始回调内），不影响战斗
- 玩家死亡/掉线时跳过该玩家（按存活判断）
- 一局的海克斯**发放次数可调**：房主开局选择 0/1/2/3 次；若入局前勾选「开启随机箱子」且房主未手动设置，则默认选 **3**，否则默认 **不启用**。减少次数时**去掉后面的发放**：
  - 3 次 = 第 5、11、18 回合
  - 2 次 = 第 5、11 回合
  - 1 次 = 第 5 回合

## 4. 符文池设计（用户定稿）

### 4.0 发放节奏与稀有度概率

三档稀有度「彩 / 金 / 银」对应素材边框色（银 = `augmentcard_frame_silver`，金 = `augmentcard_frame_gold`，彩 = `augmentcard_frame_prismatic`，见 5.0.2）：

| 发放 | 回合 | 彩 / 金 / 银 概率 |
| ---- | ---- | ---------------- |
| 第 1 个海克斯 | 第 5 回合 | **5% / 30% / 65%**（银色提高、彩色降低） |
| 第 2 个海克斯 | 第 11 回合 | **10% / 40% / 50%**（默认基准） |
| 第 3 个海克斯 | 第 18 回合 | **10% / 40% / 50%**（默认基准） |

> 默认基准概率为 彩/金/银 = 10% / 40% / 50%；仅第 1 次（第 5 回合）银色概率提高至 65%、彩色降低至 5%。

**全局规则：**

- 每回合**出兵时**给予 buff（非仅选择时），海克斯默认**只作用于自己的单位**（个别"全体效果"符文除外）
- 通用带兵种符文会展开为**四个独立候选**：步兵 / 载具 / 飞机 / 海军。不同兵种版本可同时出现在一次三选一中，也可被同一玩家分别持有；个别符文可以限制当前开放的兵种版本（无限火力目前只开放飞机），禁海模式下移除海军版本
- 一局的海克斯**发放次数可调**（入局前未开启随机箱子时默认 0 次，开启时默认 3 次；2 次 = 第 5、11 回合；1 次 = 第 5 回合；减少时去掉后面的发放）
- **启用方式联动**：与「抽卡功能 / 开启随机箱子」同理——若玩家在游戏前选择了**「开启随机箱子」**，则**一同视为开启海克斯系统**

### 4.0.1 当前已实现符文完整数值（以项目代码为准）

当前共有 **13 个基础定义**：银 4、金 7、彩 2。银色四项均展开为四个兵种版本，金色瞄准镜展开为四个兵种版本，彩色瞄准镜展开为四个兵种版本；无限火力目前仅展开飞机版本。因此非禁海模式共有银 16、金 10、彩 5 个实际候选；禁海模式移除海军版本后为银 12、金 9、彩 4 个实际候选。

| 阶级 | 符文 | 游戏内描述 | 实际数值与执行方式 |
| ---- | ---- | ---------- | ------------------ |
| 银 | 大力（兵种） | `%s单位造成的伤害提高 25%。` | 动态创建 `DAMAGE_MULT = 1.25`，即该兵种伤害 ×1.25。每回合出兵后，按选择者在该具体单位类型上的 `UNITCOUNT` 配额分配战斗单位并施加。 |
| 银 | 迅捷（兵种） | `%s单位攻击速度提高 25%。` | 动态创建 `RATE_OF_FIRE = 1.25` 的 AttributeModifier；特殊充能/弹药武器的实际收益仍需实机验证。 |
| 银 | 巡猎（兵种） | `%s单位移动速度提高 25%。` | 动态创建 `SPEED = 1.25`，即该兵种移动速度 ×1.25，持续 `9999`；不修改攻速、转向、射程或弹道速度。每回合只作用于按选择者单位池数量分配到的对应兵种战斗单位。 |
| 银 | 万用瞄准镜（兵种） | `%s单位射程提高 15%。` | 动态创建 `RANGE = 1.15`，即该兵种射程 ×1.15。卡框颜色已经表达阶级，标题不再附加“·银”。 |
| 金 | 穿云定海 | `在你的基地生成 1 个摇光，并由系统回收进单位池。` | 在 `Player_N_Start` 附近为选择者自己的队伍生成 `CelestialAdvanceAircraftTech4`，并标记为脚本生成单位，随后交给现有 `unitgetcountanddelet` 回收计数流程进入单位池。摇光“限造 3 个”改用独立的实际生产计数，因此这只赠送摇光不占生产额度。剩余生产额度统一限制在 `0～3`；回收赠送摇光不会增加额度，回收实际生产部分最多恢复到 3。 |
| 金 | 石油王 | `在你的基地获得两个油井。` | 在选择者出生点附近生成两个归属该玩家队伍的 `oilderrick`。 |
| 金 | 买二送一 | `%s单位买二送一。` | 为每名玩家生成三选一事件时，就从其自身阵营的有效 `UNITLIST` 单位中独立随机确定并固定目标，悬浮详情会直接显示如“动员兵单位买二送一”；点击时不会重新随机。效果复用狂热武士的回收计数时机，每累计两个目标单位直接向 `UNITCOUNT` 和 `ANYUNITCOUNT` 赠送一个，不生成待回收实体，因此不会递归计数。 |
| 金 | 启动资金 | `立即获得 10000 资金。` | 选择时仅给选择者执行一次 `PLAYER_GIVE_MONEY +10000`；不是持续收入，不影响队友。 |
| 金 | 固若金汤 | `己方当前仍存活的最前端防御塔最大生命提高 1500。` | 选择时执行一次。玩家 1～3按 `T71→T72→T73→T74`、玩家 4～6按 `T81→T82→T83→T84` 查找，只对遇到的第一座存活塔增加 1500 最大生命。已摧毁的塔不会复活；代码只明确设置最大生命，当前生命是否同步补充需实机确认。 |
| 金 | 破烂王 | `你的单位回收收益提高 20%。` | `最终回收倍率 = 原回收倍率 ×1.2`，是乘算提高 20%，不是直接增加 20 个百分点。例如原回收率 70% 时变为 84%。只影响选择者。 |
| 金 | 万用瞄准镜（兵种） | `%s单位射程提高 25%。` | 动态创建 `RANGE = 1.25`，即该兵种射程 ×1.25。卡框颜色已经表达阶级，标题不再附加“·金”。 |
| 彩 | 无限火力（飞机） | `飞机单位获得无限弹药。` | 作为带兵种符文记录为 `prismatic_infinite_ammo:aircraft`。参考空军元帅苏霍伊：对按选择者飞机单位池数量分配到的飞机，把武器槽 1～5写入 `100000` 弹药；选择时补施加一次，之后每回合出兵完成后再次执行。不复制空军元帅的无敌及其他属性 Buff。数据结构支持以后在 `UnitTypes` 中开放其他兵种。 |
| 彩 | 万用瞄准镜（兵种） | `%s单位射程提高 35%。` | 动态创建 `RANGE = 1.35`，即该兵种射程 ×1.35。卡框颜色已经表达阶级，标题不再附加“·彩”。 |

**破烂王的实际回收率：**

| 经济倍率 | 项目基础回收率 | 取得破烂王后 |
| -------- | -------------- | ------------ |
| 0.5 | 90% | 108% |
| 1.0 | 70% | 84% |
| 1.5 | 50% | 60% |
| 2.0 | 35% | 42% |

非纯抽卡模式还会先计算队伍中的苏联“大生产”修正：0/1/2/3 层对应 ×1 / ×0.75 / ×0.70 / ×0.65，最后再乘破烂王的 ×1.2。例如正常经济倍率、1 层大生产时为 `70% ×0.75 ×1.2 = 63%`。纯抽卡模式不应用大生产削减。

**兵种版本与判重：**

- 兵种版本使用 `基础符文ID:unitType` 作为完整持有 ID，例如 `silver_strength:infantry` 和 `silver_strength:vehicle` 是两个不同符文。
- 同一轮三选一允许同时出现同名但兵种不同的符文；同一玩家也可以分别持有这些版本。
- 同一轮的三个候选始终无放回抽取。跨轮是否允许再次出现由 `HextechRune.NonRepeatableRuneIds` 独立控制；当前仅 `gold_fortified`（固若金汤）不可重复，玩家持有后会从其后续候选池排除。
- 未列入不可重复表的符文可以跨轮再次出现；每次选择记录独立效果实例，使持续 Buff 能按实例分别加载。买二送一会保留多份独立目标/计数状态，破烂王每次取得累加 20% 回收倍率。
- 即使玩家当前还没有生产对应兵种，该兵种版本仍可进入候选池，以便作用于之后生产或刷新的单位。
- 禁海时不生成海军版本，其余三个兵种版本不受影响。

**兵种作用范围：**

| 兵种 | 当前过滤范围 |
| ---- | ------------ |
| 步兵 | `INFANTRY`；排除建筑、飞机、船只和残骸 |
| 载具 | `VEHICLE`、`HUGE_VEHICLE`；排除建筑、飞机、船只和残骸 |
| 飞机 | `AIRCRAFT`；排除建筑和残骸 |
| 海军 | `SHIP`；排除建筑和残骸 |

伤害、攻速、移速和射程类效果使用与缩小模式一致的 `9999` 持续时间。系统以战斗单位 `objectId` 保存“配额归属玩家 + 已施加的符文实例 ID”，并保留单位句柄识别 ID 复用；因此同一单位的同一持有实例只加载一次，可重复符文的新实例仍能独立生效。玩家在本回合中途选到新符文时，会给该玩家已登记且仍存活的单位补施加这个新实例，不会重复加载已有实例的 Modifier。

**混编战斗单位的玩家配额分配：**

- 实际战斗复制体统一属于 `PlyrCivilian`（玩家 1～3）或 `PlyrCreeps`（玩家 4～6），不能再用 `Player_1～6 + SAME_PLAYER` 判断原始归属。
- 系统对每一种 `UNITLIST[unitIndex]` 分别扫描场上实例，先排除已有有效标记的幸存单位，再按阵营内玩家顺序及 `UNITCOUNT[playerIndex][unitIndex]` 切分本次新单位。例如本次新增 10 只天狗，A 的单位池为 3、B 为 6、C 为 1，则 `[1..3]` 视为 A 的配额、`[4..9]` 视为 B 的配额、最后 1 只属于 C；具体是哪几只实体不重要。
- 同一玩家拥有的多个对应兵种符文可以叠加在自己的同一配额切片上；不同玩家的切片互不重叠。场上数量少于记录数量时截断，超过单位池总数的额外单位不处理。
- 兵种仍通过 `INFANTRY / VEHICLE / HUGE_VEHICLE / AIRCRAFT / SHIP` 查找表判断，因此单位池配额负责区分玩家，兵种过滤负责决定某个符文是否适用于该实体。
- 固定回合出兵与“补充军队”共用同一个新单位处理入口。“补充军队”原流程分两段生成，原有 `ShrinkMode_Trigger` 位于两段之间，因此在全部生成结束后延迟 1 tick 再补扫一次；单位标记保证前半段不会被重复加载。
- 当前测试版为每个已实现符文输出 `[海克斯测试]` `_ALERT()` 汇总：持续符文打印触发来源、玩家、符文名、本次归属/检查数、符合兵种并实际施加数及具体倍率；启动资金、固若金汤、破烂王分别打印资金、塔生命变化和回收倍率，无限火力打印处理数量及弹药值。

## 5. 技术约束与自定义图片机制

### 5.0 本图 Lua 开发约束（重要）

| 约束 | 说明 |
| ---- | ---- |
| Lua 4.0 语法 | 整个 `lua/` 目录只支持 Lua 4.0，不能用 5.x 新语法（如 `goto`、位运算符、`table.unpack` 等） |
| 闭包限制 | **Lua 4.0 不支持闭包访问外层局部变量**（不能 access outer-scope variable）。写回调/嵌套函数时，外层变量必须通过参数传入或提升为全局变量 |
| `#!ra3luabridge` 前缀 | 每个 Lua 执行块必须以 `#!ra3luabridge` 开头，否则 RA3LuaBridge 不执行该代码。开发时 lua 文件带此前缀，同步进 `ScriptsData.json` 时由脚本自动保证 |
| 源码与地图脚本的关系 | `DSA_ggz/lua/` 里的全部 lua 是对 `ScriptsData.json` 的**拆分**；`ScriptsData.json` 是地图实际加载的脚本。改 lua 后需同步回 JSON（见 `analysis/sync_lua_to_json.py` 等工具） |
| 注释 | lua 文件里的注释是给开发者看的；同步进 ScriptsData.json 的只保留执行片段 |

### 5.0.1 自定义图片机制（huohuo.webp 示例）

地图支持插入**自定义图片**（webp），用于按钮图标、UI 图像等。参考实现位于 `lua/LUABOX/BUTTON/CenterTopBtnFunc.lua`（第 1150 行起，投降按钮图标）：

**核心 API 调用链：**

```
1. exTextureCreateFromBase64(base64字符串, "DXT5")
   → 返回 textureId（从 base64 数据创建纹理）

2. exPackedTextureImageCreate({
       Texture = textureId,          -- 上一步的纹理
       CoordsX = 0, CoordsY = 0,     -- 贴图在纹理中的位置
       DimensionsX = W, DimensionsY = H,        -- 显示尺寸（如 126x126）
       TextureDimensionsX = W, TextureDimensionsY = H,  -- 源纹理尺寸
       Rotated = 0
   })
   → 返回 imageId（可复用的图片 ID，存到全局变量）

3. 使用：
   - 顶部按钮：IconId = imageId（数字 ID），经 exCenterTopBtnShowForPlayer 显示
   - 其它 IconId 也可以用内置纹理名字符串（如 'Button_PlayerPower_FreeTrade'）
```

**base64 数据来源（已实测验证）：**
- 嵌入的 base64 解码后就是一张 **webp 图片文件**本身（缩略/缩放后的版本）
- 例：`huohuo.webp` 源文件 700x700，嵌入按钮的 base64 解码后是 **126x126** 的 webp（7722 字节）
- 所以流程是：**图片 → 缩放/居中裁剪 → webp → base64 → Lua 嵌入**

**一键转换工具：**

已提供脚本 `analysis/img_to_lua.py`（依赖 Pillow）：

```
python analysis/img_to_lua.py 图片.png --size 126 --var-name g_MyIconId --embed-name my_icon --output out.lua
```

- 自动居中裁剪为正方形并缩放到指定尺寸
- 输出可直接粘贴进 Lua 的完整代码（local 表 + 两条 ex 调用）
- 生成代码与 huohuo 例子的格式完全一致

**注意事项：**
- base64 用 Lua 长字符串 `[[ ... ]]` 包裹，可换行，勿用普通字符串
- `exTextureCreateFromBase64` 的格式参数固定传 `"DXT5"`
- 每个图片生成独立的 `embed-name`（local 表名），避免变量冲突
- 图片 ID 生成一次后存全局变量，可被多个按钮/UI 复用

### 6.5 已知技术要点（坑与对策）

1. **游戏模式对话框选项上限**
   现有 6 个选项 + 确认按钮 = 7 个选项，正好卡满 `exShowCustomBtnChoiceDialogForPlayer` 的 10 参数上限。直接加第 7 个选项会超限。
   **当前实现**：主菜单选项 4 进入抽卡模式子菜单，选项 5 进入海克斯符文次数子菜单，选项 6 进入更多选项；主对话框仍保持 6 个入口 + 1 个确认按钮。

2. **对话框按钮只能显示文字**
   房主配置对话框按钮无法展示富文本/多行描述；符文选择已改用自定义卡框按钮，可通过按钮 `Desc` 显示悬浮信息并配合自定义文字。
   **当前实现**：使用“紧凑竖向稀有度卡框 + 顶部居中日冕原生图标 + 下方居中标题 + 原生悬浮详情”。卡面不直接显示效果正文；事件图标按钮与卡框按钮执行同一选择。针对日冕文字实际视觉中心偏左，事件卡标题额外右移 8 像素，面板小卡标题按比例右移 2 像素。

3. **同轮无放回与跨轮不可重复名单分离**
   同一轮的候选从筛选池无放回抽取，因此三张不会是同一个完整符文。跨轮仅 `NonRepeatableRuneIds` 中的符文按持有状态排除；无兵种符文以 `runeId`、带兵种符文以 `runeId:unitType` 记录身份。当前名单只有固若金汤。`PlayerOwnedRunes[playerIndex]` 保存每次选择的完整实例，不同玩家状态相互独立。

4. **增益施加时机**
   进攻/防御类符文需对「本方对应兵种的单位」生效，且后续新造单位也要吃到增益。
   **对策**：战斗单位混编完成后，先按具体单位类型扫描阵营单位，再依次按三名玩家对应的 `UNITCOUNT` 数量切片，最后按「兵种标签」给各自切片施加 Buff。这样不依赖混编后的所有权，也不会把一名玩家的符文扩散给同阵营全部单位；「全体效果」符文单独标记，不受该分配规则限制。

5. **兵种独立候选与效果过滤**
   通用带兵种符文在候选池中展开为步兵 / 载具 / 飞机 / 海军四个独立项，即使玩家当前尚未生产对应兵种也允许选择，以覆盖之后生产或刷新的单位。个别符文可通过 `UnitTypes` 限定当前开放版本；无限火力目前只开放飞机。
   **对策**：用 `CreateObjectFilter` 按兵种施加效果；海军版本在禁海模式下从候选池中排除（`g_DisableSeaArmy == 1`）。
