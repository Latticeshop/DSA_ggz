## 1. 背景与目标

借鉴英雄联盟斗魂竞技场的**三选一强化符文**肉鸽机制：每隔若干回合，每位玩家独立看到 3 个随机符文，选择 1 个获得，效果可持续整局、可叠加成长。本方案将该机制本地化到红警3日冕自走棋，形成全新的「海克斯符文」模式。

**核心目标：**

- 每名玩家在特定回合获得**三选一**符文事件，独立选择、互不影响；事件到点只入队并显示提示，卡页由玩家按 J 主动展开。因为不再自动弹卡页，同一次事件（有真人参与时）会全图播报一次「获得一个海克斯符文，请查收~」提醒查收
- 符文效果全部使用本图已有系统实现（AttributeModifier 增益、发钱、召唤等）
- 作为**新模式开关**接入现有游戏模式选择流程，房主可选开/关
- 符文池本地化设计，覆盖进攻 / 防御 / 经济 / 召唤 / 功能五大类

## 2. 核心机制总览（目标正式流程）

> 本节描述最终玩法目标。当前代码已经按“先判定全场稀有度 → 每名玩家独立筛池 → 无放回抽取 3 个不同符文”运行，并接入首批可实测符文；完整符文数量与专属图标仍待补齐，实际进度见第 6 章。

```
回合开始
  └─ RoundLuaManager._begin() 触发 HextechRune:OnRoundBegin(lvc)
       ├─ 模式开关已开启（房主选择 或 开启了随机箱子）？
       │    └─ 当前回合 ∈ 发放回合表（3/10/18/27，按次数 N 截取）？
       │         └─ 对每个存活玩家：
       │              ├─ 按稀有度概率抽定全场阶级，连回合号一起写入该玩家事件队列（真人）
       │              ├─ 显示「当前有未选择的海克斯，按'J'键展开面板」提示，不自动弹卡页
       │              ├─ 玩家按 J 才现场筛池抽 3 个（去重 + 每人独占 + 兵种标签）并展开卡页
       │              └─ 遭遇战电脑不进队列，仍在事件回合直接随机获得同阶符文 1 个
       └─ 玩家点击选择
            ├─ 记录符文 + 兵种到 PlayerOwnedRunes[playerIndex] / PlayerOwnedRuneIds[playerIndex]
            └─ 登记到回合回调 → 每回合出兵时按兵种对己方单位施加 buff
                 └─ 公共面板广播「玩家X获得了符文Y」
```

## 3. 触发时机（已确认）

本图科技自动解锁节奏（用户确认 + 脚本佐证）：

| 科技阶段 | 自动解锁回合 | 脚本触发条件（lvc） | 符文事件回合（解锁前一回合） |
| -------- | ------------ | ------------------- | ---------------------------- |
| T2（二本） | 第 6 回合 | NATURALUNLOCK__1：lvc ∈ [4,5] | **第 5 回合** |
| T3（三本） | 第 12 回合 | NATURALUNLOCK__2：lvc ∈ [4,11] | **第 11 回合** |
| T4（四本） | 第 19 回合 | NATURALUNLOCK__3：lvc ∈ [4,18] | **第 18 回合** |

- 每名玩家整局共经历 **N 次**三选一。入局前未勾选「开启随机箱子」时默认不启用；勾选时默认 3 次。房主仍可在模式菜单中手动改为 0/1/2/3 次
- 事件在**备战阶段**到点（RoundLuaManager 回合开始回调内），只写入队列并显示按 J 提示，不自动弹卡页，不影响战斗；`ShowRuneEvent` 在六名玩家都处理完后，只要本次有真人入队就调用一次 `exAddTextToPublicBoard` 全图播报 `hextech.selection.ready_broadcast`（每名玩家各播一次会变成 6 条重复刷屏，故按事件播一次）
- 玩家死亡/掉线时跳过该玩家（按存活判断）
- 一局的海克斯**发放次数可调**：房主开局选择 0/1/2/3/4 次；若入局前勾选「开启随机箱子」且房主未手动设置，则默认选 **3**，否则默认 **不启用**。减少次数时**去掉后面的发放**：
  - 4 次 = 第 3、10、18、27 回合
  - 3 次 = 第 3、10、18 回合
  - 2 次 = 第 3、10 回合
  - 1 次 = 第 3 回合

### 3.1 准确回合时长

`huihe/start` 每回合先将 `start` 计时器设为 **60 秒**，然后按当前回合计数 `lvc` 追加时间，因此实际回合时长不是固定 90 秒。设当前回合数为 `n`：

- `LV2 = 0`（初始阶段）：`T(n) = 60 + ⌈n / 2⌉` 秒。`lvcadd` 每次增加 1 秒，同时令 `lvcsr += 2`，直到 `lvcsr >= lvc`。
- `LV2 = 1`（`T72` 或 `T82` 被摧毁后）：`T(n) = 60 + 5 × ⌈n / 4⌉` 秒。`lvcadd__1` 每次增加 5 秒，同时令 `lvcsr += 4`，直到 `lvcsr >= lvc`。

例如第 10 回合在初始阶段为 65 秒，`LV2 = 1` 时为 75 秒；第 20 回合分别为 70 秒和 85 秒，第 24 回合的 `LV2 = 1` 阶段才达到 90 秒。所以所有“每 N 回合”效果应记录目标回合数，不应用固定秒数换算。

## 4. 符文池设计（用户定稿）

### 4.0 发放节奏与稀有度概率

三档稀有度「彩 / 金 / 银」对应素材边框色（银 = `augmentcard_frame_silver`，金 = `augmentcard_frame_gold`，彩 = `augmentcard_frame_prismatic`，见 5.0.2）：

| 发放 | 回合 | 彩 / 金 / 银 概率 |
| ---- | ---- | ---------------- |
| 第 1 个海克斯 | 第 3 回合 | **10% / 40% / 50%** |
| 第 2 个海克斯 | 第 10 回合 | **15% / 42% / 43%** |
| 第 3 个海克斯 | 第 18 回合 | **15% / 42% / 43%** |
| 第 4 个海克斯 | 第 27 回合 | **30% / 50% / 20%** |

> **稀有度概率**：第 3 回合彩/金/银为 10% / 40% / 50%；第 10、18 回合为 15% / 42% / 43%；可选的第 27 回合保持 30% / 50% / 20%。全场在同一次事件中共用抽出的阶级，每名玩家再按个人状态筛选该阶符文池。

**全局规则：**

- 每回合**出兵时**给予 buff（非仅选择时），海克斯默认**只作用于自己的单位**（个别"全体效果"符文除外）
- 通用带兵种符文会展开为**四个独立候选**：步兵 / 载具 / 飞机 / 海军。不同兵种版本可同时出现在一次三选一中，也可被同一玩家分别持有；个别符文可以限制当前开放的兵种版本（无限火力目前只开放飞机），任一禁用模式都会移除对应兵种版本（禁步兵 / 禁载具 / 禁空军 / 禁海，见《地图注释说明文档》§4）
- 一局的海克斯**发放次数可调**（房主可选 0~4 次；入局前未开启随机箱子时默认 0 次，开启时默认 3 次；第 4 次在第 27 回合发放；减少时去掉后面的发放）
- **启用方式只跟随局外「开启随机箱子」**：若房主在游戏前勾选了**「开启随机箱子」**，则**一同视为开启海克斯系统**（默认 3 次），抽卡也同步默认开启。**抽卡模式选择（选项 4）与海克斯符文设置（选项 5）是两个独立选项**：选项 4 不再改写海克斯次数，海克斯也不再看抽卡状态（与抽卡选项解耦）
- **「发不发某张符文」的两类限制**（都是符文条目上的模板标记，判定唯一入口是 `BuildFilteredPool`——三选一、单次重随、质变/赌怪奖励池与遭遇战电脑的随机取共用同一口径，且标记不进 `CopyRuneForCandidate`）：
  - `ExcludeOnLastFormalRound`（**按回合**）：本场已无下一次正式事件时不发（准备背包——那时升阶机会已无处兑现），判定 `HasNextFormalEvent()`。
  - `ExcludeOnFirstFormalSelection`（**按玩家**）：**玩家本场第一次正式选择**不发。现有四张：变形重组器 / 升级重组器（那时单位池还空着，整体重滚等于一张空符文）、回归基本功（同口径）、**秒速五厘米（前几回合就把樱花换成鬼樱过于超模）**。判定 `IsFirstFormalSelection(playerIndex)` = `PlayerFormalSelectionCount[playerIndex] == 0`。
  - 两者判定依据不同：后者看的是**这名玩家已经完成过几次正式选择**，与回合号无关。玩家把第 3 回合的事件攒到后面才按 J 展开，那一次仍按第一次算（按回合判定会漏拦）；第 3 回合没入队（无建筑）的玩家，其第一次选择同样被拦住（按回合判定会漏放）。计数在「完成一次选择」时 +1 且排在 `OnRuneChosen` 之后，所以同一次选择里的重随与质变 / 赌怪奖励池都还算「第一次」。

**符文效果的两类叠加方式：**

- **同族先加算合并、异族才各挂一枚实例**：大力、迅捷、神行、三档瞄准镜（通用/万用/万能）、星界躯体、歌莉娅巨人、诸神黄昏都走 `18_basics_exchange.lua: GetPerTypeStatModifier`——先由 `CountMatchingRuneCopies` 数出**同一族**在这只单位上的份数（同名多张、载具/空军两个变体、元神互锁外溢过来的都算一份），再按 `1 + (倍率 - 1) × 份数` **加算合并成一枚**修正器加载：两份 `DAMAGE_MULT = 1.5` → `1 + 0.5×2 = 2.0`（+100%，不是 2.25）；两份星界躯体 → 血 `1 + 0.75×2`、伤 `1 - 0.25×2`；两份诸神黄昏 → 伤 `1 + 0.9×2`，血量按用户授权**固定压到 50% 上限**（幂等钳制，不随份数连乘）。**只有不同族之间**才是两枚不同修正器，交给引擎乘算（歌莉娅巨人 + 星界躯体 = 血 `1.9 × 1.75`）。引擎对**同一个** modifier 实例重复加载只刷新时长、不叠加（`ExpireWarEfficiencyBuffs` 靠「同实例 + duration=1 再加载」过期就是这个机制）。敌方全频段阻塞干扰仍按持有者实例独立加载，不在本表内。
- **先在 lua 侧合并计算，再挂一个实例**：超凡邪恶（`回合数 ×3% ×相同兵种份数`）、以战养战（每个死亡的四个百分比按**该玩家自己的**份数先相加，份数与层数都按玩家分桶、不跨玩家共享）、究极生物（献祭阶级计数合成一个 Modifier）、登神（四维各自的次数合成一个 Modifier）、神圣干预（时长 `45 + 23×(份数-1)`）、固若金汤（`基础生命 ×(1 + 0.25×份数)`）、破烂王（经济档位倍率）、终极刷新（技能次数累加）。这些效果要么随回合变化、要么倍率相乘会失真，所以统一由 lua 先算好总数值，只给单位挂一个实例。
- 另有**全图单实例的引擎对象**与叠加方式无关：铁幕（`AttributeModifier_IronCurtain`）与时停（`PARALYZED` 禁用位）后加载会覆盖前者，因此所有施加/解除都改走 `g_ApplyIronCurtain` / `g_SetTimeStopFrozen` 仲裁。

**替换型符文 × 指定单位型符文：目标池互斥规则**

两类符文的交叉点必须统一裁决：**「指定单位型」= 买二送一 / 登神 / 究极生物**（三张都在选卡时随机圈定一个单位类型作为目标），**「替换型」= 出口内销 / 高平两用 / 龙息凌波 / 先进火炮 / 万岁冲锋 / 花来！/ 秒速五厘米**（把玩家的原形态单位在回收计数时换成升级形态入池）。

规则只有一条，两个方向对称：

| 玩家状态 | 原形态（如 樱花回天雷） | 升级形态（如 鬼樱特攻机） |
| -------- | ---------------------- | ------------------------ |
| 未持有该替换符文 | ✅ 可被指定（就是玩家的实际部队） | ❌ 不可指定（根本造不出来） |
| 持有该替换符文 | ❌ 不可指定（不再入池） | ✅ 可被指定（玩家的部队从此是它） |

- **实现收口在 `GetReplacementTargetFilter(playerIndex)`**（`01_rune_pool.lua`），它一次返回「本次要拉黑的单位类型」和「因为已持有而放行的升级形态」两张表，名单来源仍是唯一的 `HextechRune.UnitReplacementRunes`（`04_buff.lua` 的 `source → replacement` 映射，与 `ResolveCollectedUnitIndex` 共用）。`CreateRuneCandidateForPlayer` 把拉黑表并入既有的 `excluded`，所以**买二送一、登神、究极生物三张同时生效**；所有获取入口（三选一、重随、遭遇战电脑、质变/赌怪奖励）都经过 `BuildFilteredPool` → `CreateRuneCandidateForPlayer`，只需在这一处收口。
- **为什么不能只靠「可生产白名单」**：`CollectBuyTwoGetOneCandidates` 原本用抽卡生产池 `g_PureDrawBuildableUnitPool` 当白名单，升级形态不在池里、看起来天然被挡住。但实测**登神圈到了鬼樱**（玩家没有秒速五厘米，完全造不出来，那张卡等于空抽）——白名单有两条会失效的路径：生产池未加载时整体退回不筛选；筛选后候选为空时又退回未筛选池兜底。何况鬼樱为了承接替换计数**必须有 `UNITLIST` 槽位与回收表条目**（见第 6.5 节），在回收表口径下它就是「合法单位」。所以这条互斥必须由持有状态显式判定，不再依赖白名单的副作用。
- **升级形态要显式放行**：已持有替换符文时，玩家的部队确实以升级形态入池，圈它是有效的，因此 `ownedReplacement` 会作为额外白名单传进 `CollectBuyTwoGetOneCandidates`（`producible` 那道闸不认识它们）。究极生物走独立名单 `UltimateCreatureTargetTypes`，其中的一式磁轨炮重巡、郁金香自行迫击炮同样是替换产物，**未持有出口内销 / 花来！时也不再被圈**（名单条数不变，可用条数按持有状态浮动）。
- **先后顺序现在也管**：玩家先选登神/买二送一（圈中原形态）、之后才拿到替换型符文时，`OnRuneChosen` 的替换型分支会调用 `RemapReplacedRuneTargets(playerIndex)`，把已持有那张卡的 `TargetUnitType / TargetUnitIndex / TargetUnitName` 改指升级形态——原形态从此不再入池，不改就会永久停摆。登神已累计层数按玩家存（`AscensionStacks`），换目标不丢进度。究极生物不参与改指：它在选卡当帧直接向目标槽 `+1` 补一只，原形态槽照样能出单位。
- **静态黑名单压过上面这张表**：`RuneTargetExcludedTypes` 是「策划裁决不圈」的硬名单，`CreateRuneCandidateForPlayer` 里它**只并进 `ascension` / `ultimate_creature` 的 `excluded`**（买二送一不进），且 `CollectBuyTwoGetOneCandidates` 的 `excluded` 判定排在 `ownedReplacement` 放行之后，所以**黑名单优先于「持有即放行升级形态」**。名单里同时写了樱花回天雷 `JapanInterceptorAircraft` 与鬼樱特攻机 `JapanSakuraAttackRocket` 一起写进去，结果是：登神/究极生物对这两种形态**一律不圈**（未持有圈不到樱花、持有秒速五厘米也圈不到鬼樱）；买二送一不受影响，仍按上表走（未持有圈樱花、持有圈鬼樱）。鬼樱的替换映射（`UnitReplacementRunes`）与阶级条目（`NonProductionUnitTier = 3`）都不动——它照旧承接秒速五厘米的入池计数、照旧能按 T3 结算，只是不再当登神/究极生物的目标。
- **改指要同步两张表**：登神读的是符文对象本身（`GetAscensionRune` 每帧现取），改 `rune.TargetUnit*` 就够；**买二送一的进度存在 `g_HextechBuyTwoGetOne[playerIndex]` 的 state 里，取卡时复制过一份 `UnitIndex/UnitType/UnitName`**，`OnPlayerUnitCollected` 只认 `state.UnitIndex`，所以 `RemapReplacedRuneTargets` 必须同时改这份 state（`Progress` 原样继承，不重置），否则它会继续数已经不再入池的原形态槽位而断档。
- **不是每张升级形态都能被「随机圈中」**：候选只来自阵营回收表 `g_RecycleBtnsMapByFaction`（四张阵营×四页兵种）。目前只有鬼樱（在 `g_AirCraftJapan` 里有回收条目）、AC130（`g_AirCraftAllied`）与 **ZSU-85（本来就在 `g_VehicleSoviet`，`Count = 3`）** 有页内条目，持有秒速五厘米 / 先进火炮 / 轮式大炮时确实能随机圈到升级形态；**郁金香、偏流、一式、龙息炮、狂热武士只在箱子模板表 `g_CrateUnitsTemplate` 里**，即使持有对应符文也进不了随机池，只能靠上面那条「改指继承」进入登神/买二送一。给这几张补页内条目即可放开，但要同时确认回收价与兵种页归属（尚未做）。
- **改指后的池内种子计数**：`GetAscensionPooledCount` 查不到回收条目时退回 `UNITCOUNT[playerIndex][TargetUnitIndex]`，否则 `FilterAscensionUnits` 每批都会再留一只种子（升级形态只有箱子条目时会踩到）。读取口径与 `GetRecycleUnitCount` 对普通 `Type` 一致，池内有 1 只即视为已有种子。
- 新增一张替换型符文时的登记清单（缺一项就静默 no-op）：`UnitReplacementRunes`（在 `18_basics_exchange.lua`）+ `NonRepeatableRuneIds` + `SkipPerUnitAssignmentEffects` + `OnRuneChosen` 的替换型分支（四处）+ 对应兵种段的**纯计数槽**（`UNITCOUNTERINI_0.lua` 的 `UNITLIST`，不要塞进抽卡池或箱子表）+ 回收页条目（`RecycleUnit.lua`，否则替换出来的单位卖不掉、也进不了候选表）。改完跑 `analysis/check_pool_slots.py` 确认槽号没错位。
  **最容易踩的前提**：`ResolveCollectedUnitIndex` 是拿 `UNITLIST[actualUnitIndex]` 去比 `SourceType` 的，所以**源单位与替换单位都必须在 `UNITLIST` 里有槽**，否则 `g_UnitNameToUnitIndex` 取不到、替换会静默失效（场上那批单位照常按原形态入池）。轮式大炮两端都现成（源在载具段、ZSU-85 在箱子段 `g_GroundCrateUnits`），只加了映射行；`analysis/_verify_wheeled_cannon_interlock.py` 已把这条做成断言。

**破烂王的实际回收率：**

破烂王自身的加成倍率也随经济倍率变化（`g_HextechRecycleBonusRate`，未匹配的经济倍率按 20% 兜底）。

| 经济倍率 | 破烂王加成 | 项目基础回收率 | 取得破烂王后 |
| -------- | ---------- | -------------- | ------------ |
| 0.5 | ×1.1 | 90% | 99% |
| 1.0 | ×1.2 | 70% | 84% |
| 1.5 | ×1.3 | 50% | 65% |
| 2.0 | ×1.4 | 35% | 49% |

非纯抽卡模式还会先计算队伍中的苏联“大生产”修正：0/1/2/3 层对应 ×1 / ×0.75 / ×0.70 / ×0.65，最后再乘破烂王的加成。例如正常经济倍率、1 层大生产时为 `70% ×0.75 ×1.2 = 63%`。纯抽卡模式不应用大生产削减。

**兵种版本与判重：**

- 兵种版本使用 `基础符文ID:unitType` 作为完整持有 ID，例如 `silver_strength:infantry` 和 `silver_strength:vehicle` 是两个不同符文。
- 同一轮三选一允许同时出现同名但兵种不同的符文；同一玩家也可以分别持有这些版本。
- 同一轮的三个候选始终无放回抽取。跨轮是否允许再次出现由 `HextechRune.NonRepeatableRuneIds`（`01_rune_pool.lua`）独立控制，**名单以该表为唯一出处**，本文不再另行罗列；当前共 20 条（磁暴突袭已下架，注释保留不计入）。其中超凡邪恶、诸神黄昏、无限火力按 `runeId:unitType` 分别判重（同一玩家可同时持有不同兵种版本），其余按 `runeId` 判重。湮灭炸弹允许重复获得并累计部署次数。
- 未列入不可重复表的符文可以跨轮再次出现；每次选择记录独立效果实例，使持续 Buff 能按实例分别加载。买二送一会保留多份独立目标/计数状态。破烂王原本可按份数累加当前经济对应的加成档（正常经济每份 20%），现已列入不可重复表，改为玩家自身唯一。以战养战不走该表，改为玩家独立且可重复获取——多份不再放大共享 BUFF，而是把每名玩家自己的层数按份数放大，效果只作用于自身单位。
- 即使玩家当前还没有生产对应兵种，该兵种版本仍可进入候选池，以便作用于之后生产或刷新的单位。
- 禁用模式下不生成被禁兵种的版本：禁海去海军版、禁步兵去步兵版、禁载具去载具版、禁空军去飞机版；其余兵种版本不受影响。禁空时超级要塞一并被剔除（纯空军口径）。
- **只对某个具体单位生效的符文同样按兵种下架**：八张替换型符文按**源单位**的兵种、百虎上将按 `TypeSpecificRuneEffects` 登记的兵种声明 `RequiresType`，对应兵种被禁时源单位不会产出、这张卡等于空牌，所以不下架就不合理。明细见《地图注释说明文档》§4.5.1。注意**高平两用对应「禁载具」而不是「禁海」**：源单位牛蛙战车 `SovietAntiAirShip` 是载具口径（槽 134 / 回收表载具页），禁海时它以陆地形态照常上场。

**兵种作用范围：**

| 兵种 | 当前过滤范围 |
| ---- | ------------ |
| 步兵 | `INFANTRY`；排除建筑、飞机、船只和残骸；额外包含**会飞的步兵：火箭天使**（模板带 `AIRCRAFT`，光靠类别过滤器会整个漏掉） |
| 载具 | `VEHICLE`、`HUGE_VEHICLE`；排除普通飞机、船只和残骸；额外包含双形态的天狗、VX、心神及其已登记强化/水面变体 |
| 飞机 | `AIRCRAFT`；排除建筑和残骸；额外包含天狗、VX、心神、海翼、超级要塞空中要塞/大头形态及其已登记变体 |
| 海军 | `SHIP`；排除建筑和残骸；额外包含双形态的海翼与超级要塞空中要塞/大头形态 |

双形态单位使用显式 `IncludeThing` 补充表，不依赖单位当前变形后的 category：天狗（`JapanAntiInfantryVehicle`）、VX（`JapanAntiAirVehicleTech1`）、心神（`JapanMissileMechaAdvanced`）同时属于载具和飞机；海翼（`JapanAntiAirShip`）、超级要塞空中要塞/大头形态（`JapanFortressShip` / `JapanGigaFortress_Land`）同时属于飞机和海军；**火箭天使（`JapanAntiVehicleInfantryTech3`）同时属于步兵和飞机**。其它单位只按引擎原生兵种 category 判定。

伤害、攻速、移速和射程类效果使用与缩小模式一致的 `9999` 持续时间。系统以战斗单位 `objectId` 保存“配额归属玩家 + 已施加的符文实例 ID”，并以存活状态和稳定对象 ID 校验登记。只有真正获得普通持续 BUFF 或究极生物的单位保留登记（百虎上将不占配额、也不进这份登记）；无效果的单位不登记。同一玩家的一批单位先选取一次，再叠加其全部适用符文。选择符文时不再立即扫描或提前登记场上单位。

**混编战斗单位的玩家配额分配：**

- 实际战斗复制体统一属于 `PlyrCivilian`（玩家 1～3）或 `PlyrCreeps`（玩家 4～6），不能再用 `Player_1～6 + SAME_PLAYER` 判断原始归属。
- 系统对每一种 `UNITLIST[unitIndex]` 分别扫描场上实例，先排除已有有效 BUFF 登记的幸存单位。对每名持有适用效果的玩家，再从剩余同类单位中取至多 `UNITCOUNT[playerIndex][unitIndex]` 个；数量不足则全部取得。没有对应 BUFF 的玩家不占用候选单位。
- 同一玩家拥有的多个对应兵种符文可以叠加在自己的同一配额切片上；不同玩家的切片互不重叠。场上数量少于记录数量时截断，超过单位池总数的额外单位不处理。
- 兵种仍通过 `INFANTRY / VEHICLE / HUGE_VEHICLE / AIRCRAFT / SHIP` 查找表判断，因此单位池配额负责区分玩家，兵种过滤负责决定某个符文是否适用于该实体。
- 固定回合出兵与“补充军队”共用同一个新单位处理入口。`ShrinkMode_Trigger` 触发后延迟 `45` 帧（3 秒）才扫描、按 `UNITCOUNT` 切片并赋予效果；因此“补充军队”的两段生成也会在完成后被一次处理，不再提前扫描登记。
- 符文效果层与 J 键排查阶段使用的 `_ALERT()` 调试输出均已移除；玩家选择提示、错误提示以及质变/赌怪获得奖励时的全图播报继续保留。

**战场单位存活周期（全模式底层规则）**：`UnitCreate.lua` 在 `onUnitCreateEvent` 开头统一登记双方 AI 部署到战场的出生单位，默认只存活 **4 个回合**，到期在回合开始时清除，用来抑制“单位池每回合刷新导致战场实例越积越多”的兵海问题。实现走已实测的 `RoundLuaManager.DelayCallOnRoundBegin(cb, args, 回合数)`：回合过渡脚本先 `INCREMENT_COUNTER 1 "lvc"` 再 `_begin()`，而 AI 出兵在 `_begin()` 之后约 1 秒（`AIADDDELAY`）才发生，所以延迟 N 回合 = 恰好 N 个回合的战场存活。到期回调先复核 `ObjectIsAlive` → `ObjectGetInstanceId == 模板哈希` → `ObjectPlayerScriptName == 归属方`（引擎会回收 objectId，避免误杀复用了同一 id 的新单位）再 `NAMED_KILL`。覆盖项：`g_BattleUnitLifetimeRounds`（箱子开出的 `AlliedGaintAirCraftCarrier_B` 奥林匹斯级 **1 回合**、`JapanYumiAircraftCarrier` 千鸟特攻母舰 **2 回合**、`AlliedThetisBattleShip` 忒提斯战列舰 **2 回合**）；排除项 `g_BattleUnitLifetimeExcludedTypes`（`CelestialLaserTower`、`CelestialBattery`、`CelestialSpaceReinforceMarker`、`CelestialCenturionUpgradeObject`、`AlliedSuperWeapon`、`JapanGigaFortressShipEgg`、`JapanKamikazeCommandTower`、`JapanPointDefenseDrone`、`UnitCrate`/`UnitCrateNew`/`LuckyUnitCrateSeed`）。归属过滤只认 `PlyrCivilian`/`PlyrCreeps`，玩家自己生产、符文与箱子赠送给 `Player_N` 的单位一律不登记。三艘箱子船随 UNITLIST 统一注册后由本规则接管（奥林匹斯 1 回合，忒提斯与千鸟 2 回合）。

**存活周期豁免（`IsBattleUnitLifetimeExempt`）**：本规则的门槛只有「归属方是电脑方两席」+「模板注册过创建事件」，**不区分单位来源**，所以地图脚本生成的六个预设守护神与玩家技能召唤的龙船也被算了进去（4 回合后会被 `NAMED_KILL`）。现在把它们过滤掉、其余一律不变：
- **六个预设守护神**（`overlord7`/`overlord8` 模板 `Overlordtank`、`t533`/`t534` 与海塔守卫 `Sea3ProtectShip7`/`Sea3ProtectShip8` 模板 `JapanFortressShip`）：走 `g_TowerGuardianUnitIds`/`IsTowerGuardian`（BasicVar1 开局登记，权威且扛得住 `ReplaceTowerGuardian`）+ `g_BattleUnitLifetimeGuardScriptNames` 逐个脚本名比对（海塔守卫不在登记表里，只能按名字查）。**故意不按模板豁免**：`Overlordtank` 同时是 AI 装车用车、`JapanFortressShip` 也出现在别处，模板级豁免会让 AI 每回合出兵里那些车长生不老、兵海回潮。
- **技能「龙行天下」召唤的龙船**（`CelestialMCV` 家族，`CenterTopBtnFunc.RequestDragonShip` 用 `CREATE_OBJECT` 建在 `PlyrCivilian/ATTACK` / `PlyrCreeps/ATTACK` 上）：按「龙船家族模板（`g_PlayerDragonShipHashes`，由 `g_PlayerDragonShipTypes` 现算）+ 电脑方自己的攻击队」判定，与 PureDraw 的 `IsSkillDragonShip` 同口径；AI 自己名下的非龙船单位不受影响。
- 判定点有**两处**：登记入口先跳过（不排无用的到期回调），到期回调里再判一次兜底 —— 登记那一刻对象的脚本名/队名可能还没挂上，回调里（4 回合后）一定已经就绪。

**摇光（`CelestialAdvanceAircraftTech4` / `_Enhanced`）**：T4 解锁前只保留当前回合部署的批次（寿命 1 回合），T4 解锁后回到默认 4 回合。T4 状态由六个 `Player_N/UNLOCK3__N` 脚本执行时写入，统一覆盖标准模式推塔/自然解锁、死亡模式开局清塔及升本模式购买至 4 级；若在 1 回合寿命到期的那次回调里发现 T4 已解锁，则改按默认 4 回合续命而不是清除。此规则不修改玩家实际生产摇光的独立 3 个限额，箱子和符文赠送仍不占生产额度。

> 三档瞄准镜比较特殊：它跨彩/金/银三个稀有度存在，三档数值不同（15/25/50%），中文名分别为**通用瞄准镜（银）/ 万用瞄准镜（金）/ 万能瞄准镜（彩）**；每一档又按步兵/载具/飞机/海军拆成独立候选。

### 4.1 单位科技阶级表（T1~T5）

涉及 Tx 阶级的系统只有五个：**纯抽卡出货权重**、**究极生物**（只用于献祭计数，它的目标池不走这条链，见 §4 该行的独立名单）、**以战养战**、**买二送一/登神的目标池**、**重组器（变形/升级）**。它们的阶级来源统一为三段：

## 5. 技术约束与自定义图片机制

### 5.0 本图 Lua 开发约束（重要）

| 约束 | 说明 |
| ---- | ---- |
| Lua 4.0 语法 | 整个 `lua/` 目录只支持 Lua 4.0，不能用 5.x 新语法（如 `goto`、位运算符、`table.unpack` 等） |
| 闭包限制 | **Lua 4.0 不支持闭包访问外层局部变量**（不能 access outer-scope variable）。写回调/嵌套函数时，外层变量必须通过参数传入或提升为全局变量 |
| `#!ra3luabridge` 前缀 | 每个 Lua 执行块必须以 `#!ra3luabridge` 开头，否则 RA3LuaBridge 不执行该代码。开发时 lua 文件带此前缀，同步进 `ScriptsData.json` 时由脚本自动保证 |
| 源码与地图脚本的关系 | `DSA_ggz/lua/` 里的全部 lua 是对 `ScriptsData.json` 的**拆分**；`ScriptsData.json` 是地图实际加载的脚本。改 lua 后需同步回 JSON（见 `analysis/sync_lua_to_json.py` 等工具） |
| 注释 | lua 文件里的注释是给开发者看的；同步进 ScriptsData.json 的只保留执行片段 |
| **nil 键查表会报错** | 本图的 Lua 对**用 nil 当键查表**（`t[nil]`）会直接抛 `table index is nil`，不像 PC 版 Lua 4.0 那样安静返回 nil。凡是「变量可能是 nil」的地方一律先 `if x ~= nil then` 再查表，否则整条调用链当场报错（轮式大炮 `RemapReplacedRuneTargets` 曾这样崩过） |
| payload 64KB 上限 | WorldBuilder 单个 payload 约 64KB，越线内容会被截断并报 `last token read: '<eof>'` 语法错误。超过安全线（64512 B）时同步脚本会自动去注释；去注释后仍超 65536 B 就必须拆新文件/新节点，而**新节点要先在地图脚本树里加好**，否则 payload 永远不执行 |

### 5.0.1 自定义图片机制（huohuo.webp 示例）

地图支持插入**自定义图片**（webp），用于按钮图标、UI 图像等。参考实现位于 `lua/LUABOX/BUTTON/CenterTopBtnFunc.lua`（第 1150 行起，投降按钮图标）：

**核心 API 调用链：**

```
1. exTextureCreateFromBase64(base64字符串, "DXT5")
   → 返回 textureId（从 base64 数据创建纹理）

2. exPackedTextureImageCreate({
       Texture = textureId,          -- 上一步的纹理
       CoordsX = 0, CoordsY = 0,     -- 贴图在纹理中的位置
       DimensionsX = W, DimensionsY = H,        -- 显示尺寸（如 126x126）
       TextureDimensionsX = W, TextureDimensionsY = H,  -- 源纹理尺寸
       Rotated = 0
   })
   → 返回 imageId（可复用的图片 ID，存到全局变量）

3. 使用：
   - 顶部按钮：IconId = imageId（数字 ID），经 exCenterTopBtnShowForPlayer 显示
   - 其它 IconId 也可以用内置纹理名字符串（如 'Button_PlayerPower_FreeTrade'）
```

**base64 数据来源（已实测验证）：**
- 嵌入的 base64 解码后就是一张 **webp 图片文件**本身（缩略/缩放后的版本）
- 例：`huohuo.webp` 源文件 700x700，嵌入按钮的 base64 解码后是 **126x126** 的 webp（7722 字节）
- 所以流程是：**图片 → 缩放/居中裁剪 → webp → base64 → Lua 嵌入**

**一键转换工具：**

已提供脚本 `analysis/tools/img_to_lua.py`（依赖 Pillow）：

```
python analysis/tools/img_to_lua.py 图片.png --size 126 --var-name g_MyIconId --embed-name my_icon --output out.lua
```

- 自动居中裁剪为正方形并缩放到指定尺寸
- 输出可直接粘贴进 Lua 的完整代码（local 表 + 两条 ex 调用）
- 生成代码与 huohuo 例子的格式完全一致

**注意事项：**
- base64 用 Lua 长字符串 `[[ ... ]]` 包裹，可换行，勿用普通字符串
- `exTextureCreateFromBase64` 的格式参数固定传 `"DXT5"`
- 每个图片生成独立的 `embed-name`（local 表名），避免变量冲突
- 图片 ID 生成一次后存全局变量，可被多个按钮/UI 复用

### 6.3 事件触发流程

**当前项目实际流程（已实现）**：

```
HextechRune:OnRoundBegin(round)
  第 3/10/18/27 回合：
    if g_EnableHextechRune == 1 and IsFormalRound(round):
      RollFieldRarity(round)                 -- 全场统一抽出本次稀有度
      对每个仍有建筑的 Player_1..Player_6：
        真人玩家：只把本轮阶级和回合加入该玩家独立的先进先出队列，
                  并显示“按'J'键展开面板”提示——事件到点不再自动创建卡框
        遭遇战电脑：不进队列，直接随机获得同阶符文 1 个
  玩家按 J：
    若当前没有卡页：从队列取队首，按最新持有状态筛池抽 3 个并创建卡框、重随按钮后展开
    若已有卡页：在原样隐藏 / 展开之间切换（隐藏期间保留提示）
    队列为空或候选不足：清掉提示，避免反复按 J 却打不开面板
  玩家点击：
    记录真实符文和兵种标签
    立即执行一次选择效果
    隐藏并移除该玩家的 3 个按钮和文字
    刷新真实持有符文面板
    向该玩家显示选择结果
    若队列仍非空，只重新显示提示，等玩家自己按 J 展开下一份
```

**选择页与部署快捷键**：为 J、K 键分别注册独立热键命令。J 键有两种职责：**事件到点后**队列里有待选项时按 J 才首次展开卡页（正式事件一律如此，绝不自动弹出，避免玩家战斗中误触）；**已有未完成三选一时**按 J 隐藏整个选择页，再按一次原样展开。隐藏或待展开期间显示“当前有未选择的海克斯，按'J'键展开面板”。玩家拥有湮灭炸弹部署次数时，J 键提示下方持续显示“按'K'键部署湮灭炸弹”，每按一次 K 消耗一次；次数归零后提示移除。热键注册与全局回调位于 `ExtraCommand.lua`。

**当前 buff 施加时机**：`LandArmySpawn` 完成生成与混编后会启用 `ShrinkMode_Trigger`，海克斯再延迟 `45` 帧（3 秒）统一扫描。对每种具体单位，排除已有 BUFF 登记者后，仅为拥有适用效果的玩家取至多其 `UNITCOUNT` 数量，单位不足则全部赋予。同一批会叠加该玩家的全部普通持续 BUFF；究极生物每名持有者每轮出兵只进化 1 只随机目标单位；百虎上将不占单位池配额，改为按「名下全部步兵」整批发百夫长（见 §4.0.1 符文表）。只有真正获得效果的单位保留登记；选择符文时不再提前扫描。即时经济/规则效果仍在选择时登记或执行。

**“补充军队”等同于额外执行一轮出兵刷新**：`RequestSpawnArmyImmediately` 与固定回合出兵共用同一个入口——补兵同样会 `exEnableWBScript('ShrinkMode_Trigger')`，进而完整走一遍 `ApplyRoundEffects`（普通持续 BUFF 扫描 + 究极生物 + 百虎上将）。因此每次补兵都会重新按该玩家的单位池配额分配，新补出的军队会吃到全部持续 BUFF，同时**再获得一轮究极生物进化名额与一次百虎上将补发**；单位级去重（`AppliedRunes` / `UltimateCreatureRegisteredUnits` / `HextechRune.CenturionGranted` 回合号与百夫长附着物检查）保证同一只单位不会被重复叠加。这是既定行为，不是漏判回合。

### 6.5 已知技术要点（坑与对策）

1. **游戏模式对话框选项上限**
   现有 6 个选项 + 确认按钮 = 7 个选项，正好卡满 `exShowCustomBtnChoiceDialogForPlayer` 的 10 参数上限。直接加第 7 个选项会超限。
   **当前实现**：主菜单选项 4 进入抽卡模式子菜单，选项 5 进入海克斯符文次数子菜单，选项 6 进入更多选项；主对话框仍保持 6 个入口 + 1 个确认按钮。
   海克斯次数子菜单从 6 项变成 **7 项**（`不启用/一个/二个/三个/四个` + `重随次数：1次|3次` + `返回上一页`），即 `3 + 7 = 10` 参数，正好用满上限。这一页再想加第 8 行必须先合并其它行（例如把 0~4 档并成一行循环切换），否则会触发 `button_dialog.too_many_choices`。

2. **对话框按钮只能显示文字**
   房主配置对话框按钮无法展示富文本/多行描述；符文选择已改用自定义卡框按钮，可通过按钮 `Desc` 显示悬浮信息并配合自定义文字。
   **当前实现**：使用“紧凑竖向稀有度卡框 + 顶部居中日冕原生图标 + 下方居中标题 + 原生悬浮详情”。卡面不直接显示效果正文；事件图标按钮与卡框按钮执行同一选择。针对日冕文字实际视觉中心随字符数和字符类型变化的问题，三字中文事件卡/面板小卡分别右移 `14px/5px`，三字纯 ASCII（`MCV`）分别右移 `8px/2px`，四字标题分别右移 `22px/9px`，五字标题（变形重组器 / 升级重组器）分别右移 `30px/13px`（较四字档每字步进 +8px 外推）；带兵种后缀的五字标题（回归基本功 / 歌莉娅巨人，14px）按字号比例折算右移 `26px`、面板小卡仍走默认值，万用瞄准镜那三档 10px 小字号不放大。

3. **同轮无放回与跨轮不可重复名单分离**
   同一轮的候选从筛选池无放回抽取，因此三张不会是同一个完整符文。跨轮仅 `NonRepeatableRuneIds` 中的符文按持有状态排除；无兵种符文以 `runeId`、带兵种符文以 `runeId:unitType` 记录身份。名单以 `01_rune_pool.lua` 的该表为唯一出处（当前 21 条），超凡邪恶、诸神黄昏、无限火力按兵种版本分别判重。湮灭炸弹允许重复取得，每份增加一次 K 键部署次数。`PlayerOwnedRunes[playerIndex]` 保存每次选择的完整实例，不同玩家状态相互独立。

4. **跨回合选择事件排队**
   每名真人玩家维护独立 `PlayerEventQueues`，**所有正式事件一律只入队**（只入队、到点再发）：第 3/10/18/27 回合到点时只记录全场已经抽定的阶级和回合号，不创建卡框、不覆盖当前 `PlayerOptions` 和 UI，只显示按 J 的提示。玩家主动按 J 才取队首、按该玩家最新持有状态筛池生成候选，因此前面刚取得的唯一符文会正确从后续池中排除；选完一份后若队列仍有事件，也只重新显示提示，等玩家再按 J。遭遇战电脑仍在事件回合直接随机获得符文，不进入队列。

5. **选择页显隐状态**
   `PlayerSelectionVisible` 只记录当前三选一是否显示。J 键有两种行为：`PlayerOptions` 为空时按 J 触发 `ShowNextQueuedRuneEvent`（出队、筛池、建卡并展开）；已有卡页时在隐藏 / 展开之间切换，隐藏时保留所有选择数据并显示顶部提示，再次按 J 恢复同一组选项。队列为空或候选不足时提示会被清掉，避免玩家反复按 J 却打不开面板。热键通过 `ExtraCommand.lua` 的全局 `onUserHotKeyEvent` 转发，避免多个脚本重复定义全局回调相互覆盖。

6. **增益施加时机**
   进攻/防御类符文需对「本方对应兵种的单位」生效，且后续新造单位也要吃到增益。
   **对策**：战斗单位混编完成后，先按具体单位类型扫描阵营单位，再依次按三名玩家对应的 `UNITCOUNT` 数量切片，最后按「兵种标签」给各自切片施加 Buff。这样不依赖混编后的所有权，也不会把一名玩家的符文扩散给同阵营全部单位；「全体效果」符文单独标记，不受该分配规则限制。

7. **兵种独立候选与效果过滤**
   通用带兵种符文在候选池中展开为步兵 / 载具 / 飞机 / 海军四个独立项，即使玩家当前尚未生产对应兵种也允许选择，以覆盖之后生产或刷新的单位。个别符文可通过 `UnitTypes` 限定当前开放版本；无限火力目前只开放飞机。
   **对策**：用 `CreateObjectFilter` 按兵种施加效果；海军版本在禁海模式下从候选池中排除（`g_DisableSeaArmy == 1`）。

## 7. 运行规则补充（现行口径）

### 7.1 协议授予：跨阵营钥匙基地

- **硬前提**：协议绑定对应阵营的建造厂（盟军 `AlliedConstructionYard` / 苏联 `SovietConstructionYard`），**只有基地车（MCV）不算**；引擎在**施放时持续检查**持有，所以「授予后再拆基地」不成立，`UNPACKING` 状态也撑不过展开。
- **统一入口**：`16_cryo_satellite.lua` 的 `ProtocolGrants[Effect] = { PlayerTech, SpecialPower, Faction, YardType }` + `GrantProtocol(playerIndex, grantKey)`。`Faction` 按 `g_PlayerSide`（1 盟军 / 2 苏联 / 3 帝国 / 4 神州），同时是抽卡过滤依据（本阵营不再抽到自己的协议）。新增协议符文只改这张表 + 池条目 + 文案，派发不用动。
- **非同阵营**：`EnsureProtocolYard` 在 `g_PlayerSide[playerIndex] ~= grant.Faction` 时，于地图外（`ProtocolYardOffmapX/Y = 3324.27 / 8979.87`）生成 `YardType`，脚本名 `HextechProtocolYard_<faction>_<playerIndex>`，用 `GetObjectByScriptName` 判存去重（同阵营多张卡共用同一栋）。生成 **53 帧（约 3.5 秒，覆盖整段展开）** 后由 `DisableProtocolYard` 挂 `HELD` 禁用：基地造不了兵、不提供建造页，但协议按钮仍可用。
- **持有规则**：同一张协议本人唯一；队友各拿一张时各生成自己的钥匙基地——**叠同一图外坐标、图标重复都可以接受，不要加偏移**。
- **重解锁**：`ReunlockProtocol` 延迟 1 帧按位置参数解禁协议科技并清零技能倒计时；被动协议（自由贸易、大生产）走 `ReunlockPlayerTech`，只解科技锁。
- **上线状态**：冷冻卫星（`gold_cryo_satellite`）、现金奖励（`gold_cash_reward`）留档未上线；神威（时空裂缝 2 级）、鸡汤来咯（毒质腐蚀）、艾卡西亚的惊喜（时空炸弹 3 级）、享辐（投毒 3 级）、万象天引（磁力奇点）均在池。

### 7.2 玩家退出继承

- **只同侧继承**：座位 1/2/3 = 恶魔（面板左列）、4/5/6 = 天使（右列）；`FindPowerSlotBeneficiary` + `IsPowerSlotAvailableBeneficiary` 只在本侧找承接者。**1v1 同侧无人，永远不继承**——退出即 `LosePlayerAssets`，那一行从面板消失（未生效权益一并消失）。
- **归属表**：`PlayerSlotOwner[seat]` 记录每格归谁；`TransferPlayerSlotRunes(fromIndex, toIndex)` 把 `PlayerSlotOwner[slot] == fromIndex` 的**整组座位**一次性改挂，级联或多人同时退也按这条判据处理；`g_PowerSlotVacated` 保证同一席位只判一次，反复改挂不会重复发符文。
- **卡不动**：`TransferOwnedRuneToPlayer` 只合并效果聚合，不碰 `PlayerSlotOwnedRunes[seat]`，所以历史卡留在原座位；面板侧只换名字与颜色（见 §6.6）。
- **一回合多次选择**：玩家名下 N 个座位，每回合就按座位入队 N 次选择、各落对应格子；3v3 全接手 = 3 次/回合，面板三行分别为白 / 金 / 金。
- **2v2 / 3v3 空位不留白**：面板按 `IsPanelSeatOccupied` 过滤后连续排列（固定座位号顺序，不查出生点）。4v4 未支持：每列只定义 3 行，第 4 个座位显示不出来（不崩）。

### 7.3 未生效权益的继承（队列 / 在选 / 准备背包 / 顺手的事）

| 状态 | 处理 |
| ---- | ---- |
| 排队未展示的事件（`PlayerEventQueues`） | 逐条搬进继承者队列并保留原槽位：`tinsert(toQueue, { Rarity, Round, Slot = event.Slot or fromIndex })`；搬完 `PlayerEventQueues[fromIndex] = {}`，避免二次发放。 |
| 退出时正开着、还没点的三选一 | 用 `PlayerOptionSlot` / `PlayerOptionRarity` 补成一条事件入队（`Slot = pendingSlot or fromIndex`）。 |
| 准备背包 `PendingRuneAscend` / 顺手的事 `PendingExtraRunePick` | 按**次数相加**转给继承者；退出者「已生效、还差一次点击」的 `PlayerExtraPickRemaining` 另 +1。 |
| 电脑继承者 | `GrantRandomRuneToComputer(toIndex, Rarity, Round, Slot)` 按同阶池直接抽成符文（与电脑平时「没有界面就随机拿」同口径），不吞次数。 |
| 重随次数 | **不继承**（`PlayerRerollUsed` 清空）；补进来的那次选择自带一次新重随。 |

- **计数化（准备背包 / 顺手的事）**：取得 `= (旧值 or 0) + 1`；生效走 `CommitAscendRuneRarity` / `ConsumePendingExtraPick` 各 `- 1`，减到 0 才置 nil（不留 `0` 被 `if` 误判为真）；**单次选择仍只 +1 张 / 升一阶**，不随份数变大；顶阶不白花（`CanAscendRuneRarity` 要求 `rarity > 1`）。电脑路径判 `> 0` 后扣 1 再递归抽。
- **张数上限**：单座位理论最多 4 次正式事件 × (1 + 顺手的事 1) = 8 张；常见 5 张。面板按 `PanelMaxRuneCount = 5` 截断**显示**，效果照常生效；`PanelIndexSlotCount = 6` 只用于 index stride 与 `HidePanel` 清理。
- **已知边界**：继承来的待选事件排在继承者自己队列**后面**，一次会连着选好几张（欠账一次补完）——设计如此，不算 bug。

**注意**：
- **TARGETS 的定位关键字必须同时在「JSON 现有 payload」与「新 lua 内容」里出现**，否则 sync 报 `expected 1 ScriptsData payload(s) ... found 0` 并拒绝改写（实测：一次误编辑删掉 `function HextechRune:ApplyUltimateCreatures` 的函数头后同步，该符号从 JSON 侧消失，下一次同步就定位不到这个 payload）。改名或删函数时先换 needle 再 sync。`check_lua_balance.py` 只查 `for` 语法与块平衡，**发现不了丢失的函数头**，改过大文件后另按括号深度复核一次结构。
- 单个 payload 的硬上限约 65536 B，超了游戏内会报 `last token read: '<eof>'`。改大文件前先跑 `--check-only` 看余量：越线会自动去掉 Lua 注释后再发（源文件始终保留注释），去注释后仍超限则直接报错中止，避免把截断内容写进 `ScriptsData.json`。
- **新符文优先单独成包**：以战养战与时间裂隙各为独立 Script 节点 `07_war_efficiency.lua` / `08_time_rift.lua`（`HextechRuneWarEfficiency` / `HextechRuneTimeRift`，排在 `HextechRuneAscension` 之后加载；`04_buff.lua` 去注释后放不下），缩小射线同样独立成包（`09_shrink_ray.lua` → `HextechRuneShrinkRay`，排在时间裂隙之后），`04_buff.lua` 只留三处一行调用（`ApplyRoundEffects` / `ApplyNewBattleUnitEffects` / `OnRuneChosen`）。后续再加大效果文件时按同一手法拆分，不要在 `04_buff.lua` 里堆。
- **符文与技能组的同种效果不换模板，改在 lua 侧仲裁**：效果本体必须与技能组同款且已验证（铁幕 `AttributeModifier_IronCurtain`、时停 `PARALYZED`），冲突统一由 `CenterTopBtnFunc.lua` 里的共享函数收口，所有施加/解除站点都走它们，不再挑「本地图没被占用」的替代模板（那些模板的免疫口径无从验证）。
  - `g_ApplyIronCurtain(unit, duration)`：铁幕的到期由引擎定时器自己负责，没有人需要「解除」，所以只要取最长——按 `ObjectGetId → 最晚到期帧` 记录，已有租约剩得比本次长就跳过加载，短的一次永不截断长的。（未仲裁前实测：神圣干预 45 帧内放铁幕演说 196 帧，3 秒后全场铁幕一起被清除。）
  - `g_SetTimeStopFrozen(unit, refName, holderKind, frozen, duration, fxDuration)`：`PARALYZED` 是**没有定时器的共享布尔位**，必须按持有者登记租约（`native` = 技能组时停，`rift` = 时间裂隙），两份租约都过期才写 false。裂缝特效 `AttributeMod_ChronoRiftEffect` 同名也只有一份，只在能延长它时才加载，因此原生施放写入的 1e8/1e6 帧不会被符文的 45 帧截断。束缚类模板（`AttributeMod_CelestialNukeVehicleLaunchSelfParalyze` 等）实测下单位**仍能开火**，不是真时停，不再考虑。
  - `g_SweepStuckTimeStopFreeze`：布尔位漏解除＝全体永久定身，而全图只有原生计时器到点的 Else 分支会解除。凡冻过的对象都留在登记表里，每 30 帧（2 秒）复核一次，租约全过期却仍标着冻结的补一次解除，同时回收已死亡或已解除的条目。登记表只存 `ObjectGetId` 的数字 id 和引用名，**不缓存单位句柄**；存活判断走 `ObjectIsAlive(id)`，真要解除时才 `GetObjectById(id)` 现取句柄——实测：时间裂隙结束那帧用缓存句柄查存活会报 `error: table index is nil`（阵亡对象的句柄喂给引擎即以 nil 作表索引）。
  - **`g_IsIronCurtainActive` / `g_IsTimeStopActive`（符文侧的释放前过滤）**：仲裁函数保证「不截断」，但符文仍会去动一个已经带着同类效果的单位（延长或重写布尔位）。两个谓词直接读上面两张登记表回答「这个单位现在已经有铁幕 / 时停了吗」，让符文只覆盖「还没有」的那部分单位：神圣干预跳过 `g_IronCurtainExpireFrame[id] > now` 的单位，时间裂隙跳过 `native`/`rift` 任一条租约未到期的单位。**取最长的仲裁逻辑原样保留**（过滤只决定「动不动这个单位」，一旦决定施加，仍由 `g_ApplyIronCurtain` / `g_SetTimeStopFrozen` 按租约取最长）。被跳过的单位由原来那条更长的租约负责到期解除，时间裂隙也不会把它登记进本批解除名单。
- **逻辑只差参数的短 payload 合成一个分节文件**：时停的六段动作（`angelstop`、`angeltime_stop` 的 Then 与 Else、`devilstop`、`deviltime_stop` 的 Then 与 Else）合在 `lua/LUABOX/BUTTON/time_stop.lua`，用 `--@节名` 分段；`TARGETS` 第四项给节名即可一个文件回填多个 payload，`audit_lua_json.py` 逐节校验并计入 `SPLIT`。行数上千再拆成独立文件。
- **符文文案统一登记表 `g_LocalizationExtraText`（`03_text.lua`）**：海克斯相关的全部文案（模式名、入口/对话框、面板与阶级、单位类型、全部符文名称与描述、重随提示、广播话术、面板按钮）集中在 `lua/GAME/HextechRune/03_text.lua`，Script 节点 `HextechRuneText` 排在包内最前（`Localization.lua` 的 payload 已接近上限，余 112 B）。`Localization.get` 仍是「先查 `_text_sources`，查不到再回退 `g_LocalizationExtraText`」，读表发生在运行时，与节点加载顺序无关。新增符文/公告文案一律追加这张表。`game_mode.option.5.name`（模式选择项）与帮助手册里那段海克斯说明属于通用模式文案，仍留在 `Localization.lua`。
- **余量以实测为准**：单个 payload 超 64512 B 会自动去注释、超 65536 B 中止；改大文件前先跑 `sync_scriptsdata.py --check-only` 看余量。`04_buff.lua` 长期是最紧的一份，再往它加效果前先按上一条「新符文优先单独成包」拆出去。

## 10. 禁用模式对符文链路的影响

四个禁用模式（**禁步兵 / 禁载具 / 禁空军 / 禁海**）合成一个区块，

`IsRecombobulatorNavalIndex` / `IsTenPullSeaType` / `RequiresSea` 的地方，一律改走
`UNITCOUNTERINI_0.lua` 的统一分类判定：

| 符文链路 | 原先 | 现在 |

| 候选池兵种版本（`01_rune_pool.lua`） | `g_DisableSeaArmy == 1` 去海军版 | `BanModeRecycleCategoryEnabled(category)` 去被禁兵种版 |

| 究极生物目标（`05_ultimate_creature.lua`） | 整条跳过 `UltimateCreatureSeaTargetTypes` | `BanModeIsNameBanned(unitType) == 0`（`UltimateCreatureSeaTargetTypes` 已删除：全库零引用，禁海由 `navy` 类型禁令覆盖；`check_pool_slots.py` 的 `[E]` 段为说明文字） |

**预设守护神单位回避**：地图预置的守护神单位 —— `overlord7` / `overlord8`（旧联盟坦克模板的地编守卫）、`t533` / `t534`（双超级要塞）、

**不吃任何海克斯效果**：不加 buff，也不上 debuff。判定只有一处出处：`BasicVar1.lua` 的
`g_IsPresetGuardianUnitId(objectId)` / `g_IsPresetGuardianUnit(unit)`（名单 = `g_TargetGroupNames.PresetGuardian` 六条），
先查开局登记与塔毁后召唤写入的 `g_TowerGuardianUnitIds`，再逐个 `GetObjectByScriptName` 兜底（海塔守卫只有后者拦得住）；
`05_ultimate_creature.lua` 的 `IsPresetMapUnitId` / `IsPresetMapUnit` 只做委托。**只按对象 id、不按模板名**，
所以玩家自己造的 `JapanFortressShip` / `Overlordtank` 照常吃加成。新增「扫对象 + 挂效果」的函数也必须调用这道判定，
没有 `BattleUnitAssignments` 归属就不能绕开。

**双形态规则**（见《地图注释说明文档》§4.3）：天狗 / VX / 心神 / 海翼 / 火箭天使同时登记进它所有的兵种，只有全部被禁才消失——AI 会自动切形态索敌，只禁一个兵种时它照常上场。**超级要塞是例外**，
按纯空军登记，只禁空军就剔除（用户裁决），与 `04_buff.lua: DualUnitTypeFilters` 里
「超级要塞 = 飞机 + 海军」的登记**刻意不一致**：那张表管符文加成，不管禁用。

**改这条链路时注意**：兵种分类只有 `UNITCOUNTERINI_0.lua` 一处出处；
`analysis/check_ban_modes.py` 会拿 138 个 `UNITLIST` 槽跟回收表 / 箱子模板 / 双形态表对账，
白名单外的任何差异都算回归。另外「分类口径」与「出兵口径」是两层：
`g_BanModeSpawnExempt` 只给出兵函数用（禁海的两栖补位形态必须能生成），
池子 / 十连保底 / 重铸 / 符文一律仍按分类剔除。
