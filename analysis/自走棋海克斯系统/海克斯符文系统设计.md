## 1. 背景与目标

借鉴英雄联盟斗魂竞技场的**三选一强化符文**肉鸽机制：每隔若干回合，每位玩家独立看到 3 个随机符文，选择 1 个获得，效果可持续整局、可叠加成长。本方案将该机制本地化到红警3日冕自走棋，形成全新的「海克斯符文」模式。

**核心目标：**

- 每名玩家在特定回合弹出**三选一**符文对话框，独立选择、互不影响
- 符文效果全部使用本图已有系统实现（AttributeModifier 增益、发钱、召唤等）
- 作为**新模式开关**接入现有游戏模式选择流程，房主可选开/关
- 符文池本地化设计，覆盖进攻 / 防御 / 经济 / 召唤 / 功能五大类

## 2. 核心机制总览（目标正式流程）

> 本节描述最终玩法目标。当前代码已经按“先判定全场稀有度 → 每名玩家独立筛池 → 无放回抽取 3 个不同符文”运行，并接入首批可实测符文；完整符文数量与专属图标仍待补齐，实际进度见第 6 章。

```
回合开始
  └─ RoundLuaManager._begin() 触发 HextechRune:OnRoundBegin(lvc)
       ├─ 模式开关已开启（房主选择 或 开启了随机箱子）？
       │    └─ 当前回合 ∈ 发放回合表（3/10/18/27，按次数 N 截取）？
       │         └─ 对每个存活玩家：
       │              ├─ 按稀有度概率抽 3 个符文（去重 + 每人独占 + 兵种标签）
       │              └─ 弹出三选一对话框（选项含兵种标签）
       └─ 玩家点击选择
            ├─ 记录符文 + 兵种到 PlayerOwnedRunes[playerIndex] / PlayerOwnedRuneIds[playerIndex]
            └─ 登记到回合回调 → 每回合出兵时按兵种对己方单位施加 buff
                 └─ 公共面板广播「玩家X获得了符文Y」
```

## 3. 触发时机（已确认）

本图科技自动解锁节奏（用户确认 + 脚本佐证）：

| 科技阶段 | 自动解锁回合 | 脚本触发条件（lvc） | 符文事件回合（解锁前一回合） |
| -------- | ------------ | ------------------- | ---------------------------- |
| T2（二本） | 第 6 回合 | NATURALUNLOCK__1：lvc ∈ [4,5] | **第 5 回合** |
| T3（三本） | 第 12 回合 | NATURALUNLOCK__2：lvc ∈ [4,11] | **第 11 回合** |
| T4（四本） | 第 19 回合 | NATURALUNLOCK__3：lvc ∈ [4,18] | **第 18 回合** |

- 每名玩家整局共经历 **N 次**三选一。入局前未勾选「开启随机箱子」时默认不启用；勾选时默认 3 次。房主仍可在模式菜单中手动改为 0/1/2/3 次
- 事件在**备战阶段**弹出（RoundLuaManager 回合开始回调内），不影响战斗
- 玩家死亡/掉线时跳过该玩家（按存活判断）
- 一局的海克斯**发放次数可调**：房主开局选择 0/1/2/3/4 次；若入局前勾选「开启随机箱子」且房主未手动设置，则默认选 **3**，否则默认 **不启用**。减少次数时**去掉后面的发放**：
  - 4 次 = 第 3、10、18、27 回合
  - 3 次 = 第 3、10、18 回合
  - 2 次 = 第 3、10 回合
  - 1 次 = 第 3 回合

### 3.1 准确回合时长

`huihe/start` 每回合先将 `start` 计时器设为 **60 秒**，然后按当前回合计数 `lvc` 追加时间，因此实际回合时长不是固定 90 秒。设当前回合数为 `n`：

- `LV2 = 0`（初始阶段）：`T(n) = 60 + ⌈n / 2⌉` 秒。`lvcadd` 每次增加 1 秒，同时令 `lvcsr += 2`，直到 `lvcsr >= lvc`。
- `LV2 = 1`（`T72` 或 `T82` 被摧毁后）：`T(n) = 60 + 5 × ⌈n / 4⌉` 秒。`lvcadd__1` 每次增加 5 秒，同时令 `lvcsr += 4`，直到 `lvcsr >= lvc`。

例如第 10 回合在初始阶段为 65 秒，`LV2 = 1` 时为 75 秒；第 20 回合分别为 70 秒和 85 秒，第 24 回合的 `LV2 = 1` 阶段才达到 90 秒。所以所有“每 N 回合”效果应记录目标回合数，不应用固定秒数换算。

## 4. 符文池设计（用户定稿）

### 4.0 发放节奏与稀有度概率

三档稀有度「彩 / 金 / 银」对应素材边框色（银 = `augmentcard_frame_silver`，金 = `augmentcard_frame_gold`，彩 = `augmentcard_frame_prismatic`，见 5.0.2）：

| 发放 | 回合 | 彩 / 金 / 银 概率 |
| ---- | ---- | ---------------- |
| 第 1 个海克斯 | 第 3 回合 | **10% / 40% / 50%** |
| 第 2 个海克斯 | 第 10 回合 | **15% / 42% / 43%** |
| 第 3 个海克斯 | 第 18 回合 | **15% / 42% / 43%** |
| 第 4 个海克斯 | 第 27 回合 | **30% / 50% / 20%** |

> **2026-09-29 提高彩卡概率**（原为 5/40/55 与 10/45/45）：第 3 回合彩/金/银为 10% / 40% / 50%；第 10、18 回合为 15% / 42% / 43%；可选的第 27 回合保持 30% / 50% / 20%。全场在同一次事件中共用抽出的阶级，每名玩家再按个人状态筛选该阶符文池。

**全局规则：**

- 每回合**出兵时**给予 buff（非仅选择时），海克斯默认**只作用于自己的单位**（个别"全体效果"符文除外）
- 通用带兵种符文会展开为**四个独立候选**：步兵 / 载具 / 飞机 / 海军。不同兵种版本可同时出现在一次三选一中，也可被同一玩家分别持有；个别符文可以限制当前开放的兵种版本（无限火力目前只开放飞机），禁海模式下移除海军版本
- 一局的海克斯**发放次数可调**（房主可选 0~4 次；入局前未开启随机箱子时默认 0 次，开启时默认 3 次；第 4 次在第 27 回合发放；减少时去掉后面的发放）
- **启用方式只跟随局外「开启随机箱子」**：若房主在游戏前勾选了**「开启随机箱子」**，则**一同视为开启海克斯系统**（默认 3 次），抽卡也同步默认开启。**抽卡模式选择（选项 4）与海克斯符文设置（选项 5）是两个独立选项**：选项 4 不再改写海克斯次数，海克斯也不再看抽卡状态（2026-10-03 解耦）

**符文效果的两类叠加方式（2026-09-28 整理）：**

- **每份独立加载同一个共享 Modifier**：大力、迅捷、神行、三档万用瞄准镜、星界躯体、歌莉娅巨人、诸神黄昏（敌方全频段阻塞干扰按持有者实例独立加载）。玩家每持有一份，就对同一单位再加载一次同一个 Modifier；单位身上会同时存在多个独立实例，由引擎按属性规则依次作用（`MULT` 类为乘算：两份 `DAMAGE_MULT = 1.5` 得到 2.25 倍，不是 2.0 倍）。诸神黄昏的压血是「取上限的一半」，多份不会压得更低。
- **先在 lua 侧合并计算，再挂一个实例**：超凡邪恶（`回合数 ×3% ×相同兵种份数`）、以战养战（每个死亡的四个百分比按**该玩家自己的**份数先相加，2026-09-29 起份数与层数都按玩家分桶，不再跨玩家共享）、究极生物（献祭阶级计数合成一个 Modifier）、登神（四维各自的次数合成一个 Modifier）、神圣干预（时长 `45 + 23×(份数-1)`）、固若金汤（`基础生命 ×(1 + 0.25×份数)`）、破烂王（经济档位倍率）、终极刷新（技能次数累加）。这些效果要么随回合变化、要么倍率相乘会失真，所以统一由 lua 先算好总数值，只给单位挂一个实例。
- 另有**全图单实例的引擎对象**与叠加方式无关：铁幕（`AttributeModifier_IronCurtain`）与时停（`PARALYZED` 禁用位）后加载会覆盖前者，因此所有施加/解除都改走 `g_ApplyIronCurtain` / `g_SetTimeStopFrozen` 仲裁。

**替换型符文与目标池互斥（2026-09-28）：**

出口内销 / 高平两用 / 先进火炮 / 万岁冲锋属于「替换原单位」的符文：持有后，对应原形态在回收计数时一律被换成升级形态入池。因此该玩家的登神 / 买二送一候选池会排除这些原单位，否则圈到的目标永远不会再有单位入池，等于空抽。实现上 `HextechRune.UnitReplacementRunes`（`04_buff.lua`）是唯一的 `source → replacement` 映射表，`ResolveCollectedUnitIndex` 与 `GetReplacedSourceTypes` 共用它；`CreateRuneCandidateForPlayer` 把结果并入原有的 `excluded` 目标过滤。所有获取入口（三选一、重随、遭遇战电脑、质变/赌怪奖励）都经过 `BuildFilteredPool`，因此只需在这一处收口。替换后的升级形态本身仍是合法目标。**反向不互斥**：玩家先选登神/买二送一、后选替换型符文时，已入池的原单位不被追溯替换（替换只发生在 `unitgetcountanddelet` 回收计数那一刻），只有之后新生产的单位走替换形态——该组合按既定口径允许存在。

**兵种版本与判重：**

- 兵种版本使用 `基础符文ID:unitType` 作为完整持有 ID，例如 `silver_strength:infantry` 和 `silver_strength:vehicle` 是两个不同符文。
- 同一轮三选一允许同时出现同名但兵种不同的符文；同一玩家也可以分别持有这些版本。
- 同一轮的三个候选始终无放回抽取。跨轮是否允许再次出现由 `HextechRune.NonRepeatableRuneIds`（`01_rune_pool.lua`）独立控制，**名单以该表为唯一出处**，本文不再另行罗列；当前共 20 条（磁暴突袭已下架，注释保留不计入）。其中超凡邪恶、诸神黄昏、无限火力按 `runeId:unitType` 分别判重（同一玩家可同时持有不同兵种版本），其余按 `runeId` 判重。湮灭炸弹允许重复获得并累计部署次数。
- 未列入不可重复表的符文可以跨轮再次出现；每次选择记录独立效果实例，使持续 Buff 能按实例分别加载。买二送一会保留多份独立目标/计数状态。破烂王原本可按份数累加当前经济对应的加成档（正常经济每份 20%），现已列入不可重复表，改为玩家自身唯一。**2026-09-29：以战养战从该表移除**，改为玩家独立且可重复获取——多份不再放大共享 BUFF，而是把每名玩家自己的层数按份数放大，效果只作用于自身单位。
- 即使玩家当前还没有生产对应兵种，该兵种版本仍可进入候选池，以便作用于之后生产或刷新的单位。
- 禁海时不生成海军版本，其余三个兵种版本不受影响。

**混编战斗单位的玩家配额分配：**

- 实际战斗复制体统一属于 `PlyrCivilian`（玩家 1～3）或 `PlyrCreeps`（玩家 4～6），不能再用 `Player_1～6 + SAME_PLAYER` 判断原始归属。
- 系统对每一种 `UNITLIST[unitIndex]` 分别扫描场上实例，先排除已有有效 BUFF 登记的幸存单位。对每名持有适用效果的玩家，再从剩余同类单位中取至多 `UNITCOUNT[playerIndex][unitIndex]` 个；数量不足则全部取得。没有对应 BUFF 的玩家不占用候选单位。
- 同一玩家拥有的多个对应兵种符文可以叠加在自己的同一配额切片上；不同玩家的切片互不重叠。场上数量少于记录数量时截断，超过单位池总数的额外单位不处理。
- 兵种仍通过 `INFANTRY / VEHICLE / HUGE_VEHICLE / AIRCRAFT / SHIP` 查找表判断，因此单位池配额负责区分玩家，兵种过滤负责决定某个符文是否适用于该实体。
- 固定回合出兵与“补充军队”共用同一个新单位处理入口。`ShrinkMode_Trigger` 触发后延迟 `45` 帧（3 秒）才扫描、按 `UNITCOUNT` 切片并赋予效果；因此“补充军队”的两段生成也会在完成后被一次处理，不再提前扫描登记。
- 符文效果层与 J 键排查阶段使用的 `_ALERT()` 调试输出均已移除；玩家选择提示、错误提示以及质变/赌怪获得奖励时的全图播报继续保留。

**战场单位存活周期（全模式底层规则，2026-09-28 扩写）**：`UnitCreate.lua` 在 `onUnitCreateEvent` 开头统一登记双方 AI 部署到战场的出生单位，默认只存活 **4 个回合**，到期在回合开始时清除，用来抑制“单位池每回合刷新导致战场实例越积越多”的兵海问题。实现走已实测的 `RoundLuaManager.DelayCallOnRoundBegin(cb, args, 回合数)`：回合过渡脚本先 `INCREMENT_COUNTER 1 "lvc"` 再 `_begin()`，而 AI 出兵在 `_begin()` 之后约 1 秒（`AIADDDELAY`）才发生，所以延迟 N 回合 = 恰好 N 个回合的战场存活。到期回调先复核 `ObjectIsAlive` → `ObjectGetInstanceId == 模板哈希` → `ObjectPlayerScriptName == 归属方`（引擎会回收 objectId，避免误杀复用了同一 id 的新单位）再 `NAMED_KILL`。覆盖项：`g_BattleUnitLifetimeRounds`（箱子开出的 `AlliedGaintAirCraftCarrier_B` 奥林匹斯级 **1 回合**、`JapanYumiAircraftCarrier` 千鸟特攻母舰 **2 回合**、`AlliedThetisBattleShip` 忒提斯战列舰 **2 回合**）；排除项 `g_BattleUnitLifetimeExcludedTypes`（`CelestialLaserTower`、`CelestialBattery`、`CelestialSpaceReinforceMarker`、`CelestialCenturionUpgradeObject`、`AlliedSuperWeapon`、`JapanGigaFortressShipEgg`、`JapanKamikazeCommandTower`、`JapanPointDefenseDrone`、`UnitCrate`/`UnitCrateNew`/`LuckyUnitCrateSeed`）。归属过滤只认 `PlyrCivilian`/`PlyrCreeps`，玩家自己生产、符文与箱子赠送给 `Player_N` 的单位一律不登记。原来只写在 `01_crate_event.lua` 的 `SetCrateShipLifetime` 已删除，三艘箱子船随 UNITLIST 统一注册后由本规则接管，覆盖值与删掉的原实现一致（奥林匹斯 1 回合，忒提斯与千鸟 2 回合）。

## 5. 技术约束与自定义图片机制

### 5.0 本图 Lua 开发约束（重要）

| 约束 | 说明 |
| ---- | ---- |
| Lua 4.0 语法 | 整个 `lua/` 目录只支持 Lua 4.0，不能用 5.x 新语法（如 `goto`、位运算符、`table.unpack` 等） |
| 闭包限制 | **Lua 4.0 不支持闭包访问外层局部变量**（不能 access outer-scope variable）。写回调/嵌套函数时，外层变量必须通过参数传入或提升为全局变量 |
| `#!ra3luabridge` 前缀 | 每个 Lua 执行块必须以 `#!ra3luabridge` 开头，否则 RA3LuaBridge 不执行该代码。开发时 lua 文件带此前缀，同步进 `ScriptsData.json` 时由脚本自动保证 |
| 源码与地图脚本的关系 | `DSA_ggz/lua/` 里的全部 lua 是对 `ScriptsData.json` 的**拆分**；`ScriptsData.json` 是地图实际加载的脚本。改 lua 后需同步回 JSON（见 `analysis/sync_lua_to_json.py` 等工具） |
| 注释 | lua 文件里的注释是给开发者看的；同步进 ScriptsData.json 的只保留执行片段 |

### 5.0.1 自定义图片机制（huohuo.webp 示例）

地图支持插入**自定义图片**（webp），用于按钮图标、UI 图像等。参考实现位于 `lua/LUABOX/BUTTON/CenterTopBtnFunc.lua`（第 1150 行起，投降按钮图标）：

**核心 API 调用链：**

```
1. exTextureCreateFromBase64(base64字符串, "DXT5")
   → 返回 textureId（从 base64 数据创建纹理）

2. exPackedTextureImageCreate({
       Texture = textureId,          -- 上一步的纹理
       CoordsX = 0, CoordsY = 0,     -- 贴图在纹理中的位置
       DimensionsX = W, DimensionsY = H,        -- 显示尺寸（如 126x126）
       TextureDimensionsX = W, TextureDimensionsY = H,  -- 源纹理尺寸
       Rotated = 0
   })
   → 返回 imageId（可复用的图片 ID，存到全局变量）

3. 使用：
   - 顶部按钮：IconId = imageId（数字 ID），经 exCenterTopBtnShowForPlayer 显示
   - 其它 IconId 也可以用内置纹理名字符串（如 'Button_PlayerPower_FreeTrade'）
```

**base64 数据来源（已实测验证）：**
- 嵌入的 base64 解码后就是一张 **webp 图片文件**本身（缩略/缩放后的版本）
- 例：`huohuo.webp` 源文件 700x700，嵌入按钮的 base64 解码后是 **126x126** 的 webp（7722 字节）
- 所以流程是：**图片 → 缩放/居中裁剪 → webp → base64 → Lua 嵌入**

**一键转换工具：**

已提供脚本 `analysis/img_to_lua.py`（依赖 Pillow）：

```
python analysis/img_to_lua.py 图片.png --size 126 --var-name g_MyIconId --embed-name my_icon --output out.lua
```

- 自动居中裁剪为正方形并缩放到指定尺寸
- 输出可直接粘贴进 Lua 的完整代码（local 表 + 两条 ex 调用）
- 生成代码与 huohuo 例子的格式完全一致

**注意事项：**
- base64 用 Lua 长字符串 `[[ ... ]]` 包裹，可换行，勿用普通字符串
- `exTextureCreateFromBase64` 的格式参数固定传 `"DXT5"`
- 每个图片生成独立的 `embed-name`（local 表名），避免变量冲突
- 图片 ID 生成一次后存全局变量，可被多个按钮/UI 复用

### 6.3 事件触发流程

**当前项目实际流程（已实现）**：

```
HextechRune:OnRoundBegin(round)
  第 3/10/18/27 回合：
    if g_EnableHextechRune == 1 and IsFormalRound(round):
      RollFieldRarity(round)                 -- 全场统一抽出本次稀有度
      对每个仍有建筑的 Player_1..Player_6：
        若该玩家没有未完成选择：
          按已拥有的“基础符文 + 兵种”组合和禁海状态独立筛池
          从筛选结果中无放回抽取 3 个不同符文并创建卡框、重随按钮
        若该玩家仍有未完成选择：
          将本轮阶级和回合加入该玩家独立的先进先出队列
  玩家点击：
    记录真实符文和兵种标签
    立即执行一次选择效果
    隐藏并移除该玩家的 3 个按钮和文字
    刷新真实持有符文面板
    向该玩家显示选择结果
    若队列非空，立即按最新持有状态筛池并展示队首事件
```

**选择页与部署快捷键**：为 J、K 键分别注册独立热键命令。存在当前未完成的三选一时，按 J 可隐藏整个选择页，再按一次原样展开；隐藏期间显示“当前有未选择的海克斯，按'J'键展开面板”。玩家拥有湮灭炸弹部署次数时，J 键提示下方持续显示“按'K'键部署湮灭炸弹”，每按一次 K 消耗一次；次数归零后提示移除。热键注册与全局回调位于 `ExtraCommand.lua`。

**当前 buff 施加时机**：`LandArmySpawn` 完成生成与混编后会启用 `ShrinkMode_Trigger`，海克斯再延迟 `45` 帧（3 秒）统一扫描。对每种具体单位，排除已有 BUFF 登记者后，仅为拥有适用效果的玩家取至多其 `UNITCOUNT` 数量，单位不足则全部赋予。同一批会叠加该玩家的全部普通持续 BUFF；究极生物每名持有者每轮出兵只进化 1 只鬼王X，五虎上将仍受每份 5 个名额限制。只有真正获得效果的单位保留登记；选择符文时不再提前扫描。即时经济/规则效果仍在选择时登记或执行。

**“补充军队”等同于额外执行一轮出兵刷新**：`RequestSpawnArmyImmediately` 与固定回合出兵共用同一个入口——补兵同样会 `exEnableWBScript('ShrinkMode_Trigger')`，进而完整走一遍 `ApplyRoundEffects`（普通持续 BUFF 扫描 + 究极生物 + 五虎上将）。因此每次补兵都会重新按该玩家的单位池配额分配，新补出的军队会吃到全部持续 BUFF，同时**再获得一轮究极生物进化名额与 5×份数的百夫长名额**；单位级去重（`AppliedRunes` / `UltimateCreatureRegisteredUnits` / `FiveTigerGranted` 与百夫长附着物检查）保证同一只单位不会被重复叠加。这是既定行为，不是漏判回合。

### 6.5 已知技术要点（坑与对策）

1. **游戏模式对话框选项上限**
   现有 6 个选项 + 确认按钮 = 7 个选项，正好卡满 `exShowCustomBtnChoiceDialogForPlayer` 的 10 参数上限。直接加第 7 个选项会超限。
   **当前实现**：主菜单选项 4 进入抽卡模式子菜单，选项 5 进入海克斯符文次数子菜单，选项 6 进入更多选项；主对话框仍保持 6 个入口 + 1 个确认按钮。

2. **对话框按钮只能显示文字**
   房主配置对话框按钮无法展示富文本/多行描述；符文选择已改用自定义卡框按钮，可通过按钮 `Desc` 显示悬浮信息并配合自定义文字。
   **当前实现**：使用“紧凑竖向稀有度卡框 + 顶部居中日冕原生图标 + 下方居中标题 + 原生悬浮详情”。卡面不直接显示效果正文；事件图标按钮与卡框按钮执行同一选择。针对日冕文字实际视觉中心随字符数和字符类型变化的问题，三字中文事件卡/面板小卡分别右移 `14px/5px`，三字纯 ASCII（`MCV`）分别右移 `8px/2px`，四字标题分别右移 `22px/9px`，五字标题（变形重组器 / 升级重组器）分别右移 `30px/13px`（较四字档每字步进 +8px 外推；带兵种后缀的小字号五字标题仍走默认值）。

3. **同轮无放回与跨轮不可重复名单分离**
   同一轮的候选从筛选池无放回抽取，因此三张不会是同一个完整符文。跨轮仅 `NonRepeatableRuneIds` 中的符文按持有状态排除；无兵种符文以 `runeId`、带兵种符文以 `runeId:unitType` 记录身份。名单以 `01_rune_pool.lua` 的该表为唯一出处（当前 21 条），超凡邪恶、诸神黄昏、无限火力按兵种版本分别判重。湮灭炸弹允许重复取得，每份增加一次 K 键部署次数。`PlayerOwnedRunes[playerIndex]` 保存每次选择的完整实例，不同玩家状态相互独立。

4. **跨回合选择事件排队**
   每名真人玩家维护独立 `PlayerEventQueues`。如果第 10 或 18 回合到来时前一轮三选一仍未完成，本轮只记录全场已经抽定的阶级，不覆盖当前 `PlayerOptions` 和 UI；前一轮选完并移除按钮后立即按先进先出展示队首。候选延迟到真正展示时才按该玩家最新持有状态生成，因此前一轮刚取得的唯一符文会正确从后续池中排除。遭遇战电脑仍在事件回合直接随机获得符文，不进入队列。

5. **选择页显隐状态**
   `PlayerSelectionVisible` 只记录当前三选一是否显示。J 键隐藏时保留所有选择数据并显示顶部提示，再次按 J 恢复同一组选项；新事件首次展示以及排队事件接续展示时默认展开。热键通过 `ExtraCommand.lua` 的全局 `onUserHotKeyEvent` 转发，避免多个脚本重复定义全局回调相互覆盖。

6. **增益施加时机**
   进攻/防御类符文需对「本方对应兵种的单位」生效，且后续新造单位也要吃到增益。
   **对策**：战斗单位混编完成后，先按具体单位类型扫描阵营单位，再依次按三名玩家对应的 `UNITCOUNT` 数量切片，最后按「兵种标签」给各自切片施加 Buff。这样不依赖混编后的所有权，也不会把一名玩家的符文扩散给同阵营全部单位；「全体效果」符文单独标记，不受该分配规则限制。

7. **兵种独立候选与效果过滤**
   通用带兵种符文在候选池中展开为步兵 / 载具 / 飞机 / 海军四个独立项，即使玩家当前尚未生产对应兵种也允许选择，以覆盖之后生产或刷新的单位。个别符文可通过 `UnitTypes` 限定当前开放版本；无限火力目前只开放飞机。
   **对策**：用 `CreateObjectFilter` 按兵种施加效果；海军版本在禁海模式下从候选池中排除（`g_DisableSeaArmy == 1`）。

## 9. 编译 / 同步工具链（`tools/`）

工具位于 `analysis/tools/`，随仓库一起上传；`analysis/.gitignore` 里除 `!自走棋海克斯系统/tools/*.py` 放行外，其余 `analysis/` 下的临时脚本仍不上传。

| 文件 | 说明 |
|---|---|
| `lua_payload.py` | payload 构造公共库：CRLF 归一、超 64512 B 自动去注释、超 65536 B 报错中止 |
| `sync_scriptsdata.py` | 主力同步：lua/** → ScriptsData.json 各 payload（46 个 target，含海克斯全部文件与 Localization）。TARGETS 每项为 `(源文件, [定位关键字])`，可选第三项声明该段逻辑在 JSON 里重复几份（`EnvKillAllUnit` 一个脚本节点内有两条相同动作，两份一起覆盖才不会绕过新逻辑），可选第四项给出 `--@节名` 用于一个源文件回填多个 payload（`time_stop.lua`） |
| `audit_lua_json.py` | 全树内容审计：逐个 lua 文件在 JSON 里找对应 payload，分类 OK / CONCAT / LEGACY / COSMETIC / DRIFT；只有 DRIFT 需要处理（改完 lua 忘了同步，或 lua 与 JSON 各说各话）。不看登记名单，避免把上百个没人改过的老脚本报成问题 |
| `add_hextech_scripts.py` | 首次插入海克斯 Script 节点（建包用，节点顺序 = 脚本里的 specs 列表，新增文件后跑一次即插入） |
| `sync_utils_lucky_crate.py` | PureDraw 6 个分片拼接后同步 UtilsLuckyCrate payload |
| `sync_update_log2.py` | 单独同步 Update_0.lua（更新日志） |
| `check_lua_balance.py` | lua 源文件括号/引号/关键字平衡校验 |
| `check_payload_integrity.py` | UtilsLuckyCrate payload 结构完整性检查 |
| `check_balance_file.py` | 单文件括号平衡检查（带路径参数） |

**可移植性**：脚本统一通过 `lua_payload.find_repo_root()` 向上查找 `ScriptsData.json` 来定位仓库根，不再硬编码 `E:\Ra3_AutoChess\DSA_ggz`，在任意工作目录下都能运行。

**常用命令**（在仓库根执行）：

```bash
# 只校验不改写：比对 lua/ 与 ScriptsData.json 的全部 target
python "analysis/tools/sync_scriptsdata.py" --check-only
# 全树内容审计：找出「改了 lua 但 JSON 里没有」的真漂移（DRIFT 应为 0）
python "analysis/tools/audit_lua_json.py"
# 实际同步（单个 payload 超 64512 B 会自动去注释后再发）
python "analysis/tools/sync_scriptsdata.py"
# lua 源文件平衡校验
python "analysis/tools/check_lua_balance.py"
```

**注意**：
- `sync_update_log2.py` **没有 `--check-only`**，运行即写入（内容幂等）。
- 单个 payload 的硬上限约 65536 B，超了游戏内会报 `last token read: '<eof>'`。改大文件前先跑 `--check-only` 看余量：越线会自动去掉 Lua 注释后再发（源文件始终保留注释），去注释后仍超限则直接报错中止，避免把截断内容写进 `ScriptsData.json`。细节与实测余量见项目记忆「64KB payload 上限」。
- **新符文优先单独成包**：以战养战与时间裂隙最初写在 `04_buff.lua`，去注释后仍达 67890 B 超限，遂拆为 `07_war_efficiency.lua` / `08_time_rift.lua` 两个 Script 节点（`HextechRuneWarEfficiency` / `HextechRuneTimeRift`，排在 `HextechRuneAscension` 之后加载），`04_buff.lua` 回落到 59332 B。缩小射线按同一结论**一开始就单独成包**（`09_shrink_ray.lua` → `HextechRuneShrinkRay`，排在时间裂隙之后），`04_buff.lua` 只留三处一行调用（`ApplyRoundEffects` / `ApplyNewBattleUnitEffects` / `OnRuneChosen`）。后续再加大效果文件时按同一手法拆分，不要在 `04_buff.lua` 里堆。
- **符文与技能组的同种效果不换模板，改在 lua 侧仲裁**：效果本体必须与技能组同款且已验证（铁幕 `AttributeModifier_IronCurtain`、时停 `PARALYZED`），冲突统一由 `CenterTopBtnFunc.lua` 里的共享函数收口，所有施加/解除站点都走它们，不再挑「本地图没被占用」的替代模板（那些模板的免疫口径无从验证）。
  - `g_ApplyIronCurtain(unit, duration)`：铁幕的到期由引擎定时器自己负责，没有人需要「解除」，所以只要取最长——按 `ObjectGetId → 最晚到期帧` 记录，已有租约剩得比本次长就跳过加载，短的一次永不截断长的。（2026-09-28 实测未仲裁前：神圣干预 45 帧内放铁幕演说 196 帧，3 秒后全场铁幕一起被清除。）
  - `g_SetTimeStopFrozen(unit, refName, holderKind, frozen, duration, fxDuration)`：`PARALYZED` 是**没有定时器的共享布尔位**，必须按持有者登记租约（`native` = 技能组时停，`rift` = 时间裂隙），两份租约都过期才写 false。裂缝特效 `AttributeMod_ChronoRiftEffect` 同名也只有一份，只在能延长它时才加载，因此原生施放写入的 1e8/1e6 帧不会被符文的 45 帧截断。束缚类模板（`AttributeMod_CelestialNukeVehicleLaunchSelfParalyze` 等）实测下单位**仍能开火**，不是真时停，不再考虑。
  - `g_SweepStuckTimeStopFreeze`：布尔位漏解除＝全体永久定身，而全图只有原生计时器到点的 Else 分支会解除。凡冻过的对象都留在登记表里，每 30 帧（2 秒）复核一次，租约全过期却仍标着冻结的补一次解除，同时回收已死亡或已解除的条目。登记表只存 `ObjectGetId` 的数字 id 和引用名，**不缓存单位句柄**；存活判断走 `ObjectIsAlive(id)`，真要解除时才 `GetObjectById(id)` 现取句柄——2026-09-28 实测：时间裂隙结束那帧用缓存句柄查存活会报 `error: table index is nil`（阵亡对象的句柄喂给引擎即以 nil 作表索引）。
  - **`g_IsIronCurtainActive` / `g_IsTimeStopActive`（2026-10-03 新增，符文侧的释放前过滤）**：仲裁函数保证「不截断」，但符文仍会去动一个已经带着同类效果的单位（延长或重写布尔位）。两个谓词直接读上面两张登记表回答「这个单位现在已经有铁幕 / 时停了吗」，让符文只覆盖「还没有」的那部分单位：神圣干预跳过 `g_IronCurtainExpireFrame[id] > now` 的单位，时间裂隙跳过 `native`/`rift` 任一条租约未到期的单位。**取最长的仲裁逻辑原样保留**（过滤只决定「动不动这个单位」，一旦决定施加，仍由 `g_ApplyIronCurtain` / `g_SetTimeStopFrozen` 按租约取最长）。被跳过的单位由原来那条更长的租约负责到期解除，时间裂隙也不会把它登记进本批解除名单。
- **逻辑只差参数的短 payload 合成一个分节文件**：时停的六段动作（`angelstop`、`angeltime_stop` 的 Then 与 Else、`devilstop`、`deviltime_stop` 的 Then 与 Else）合在 `lua/LUABOX/BUTTON/time_stop.lua`，用 `--@节名` 分段；`TARGETS` 第四项给节名即可一个文件回填多个 payload，`audit_lua_json.py` 逐节校验并计入 `SPLIT`。行数上千再拆成独立文件。
- **符文文案统一登记表 `g_LocalizationExtraText`（`03_text.lua`）**：此前海克斯文案一部分在 `Localization.lua`、新增的一小部分在 `01_rune_pool.lua` 的表里，两处维护，且 `Localization.lua` 的 payload 已被占满（余 112 B）。现把海克斯相关的全部文案（模式名、入口/对话框、面板与阶级、单位类型、全部符文名称与描述、重随提示、广播话术、面板按钮）集中到 `lua/GAME/HextechRune/03_text.lua`，Script 节点 `HextechRuneText` 排在包内最前。`Localization.get` 仍是「先查 `_text_sources`，查不到再回退 `g_LocalizationExtraText`」，读表发生在运行时，与节点加载顺序无关。新增符文/公告文案一律追加这张表。`game_mode.option.5.name`（模式选择项）与帮助手册里那段海克斯说明属于通用模式文案，仍留在 `Localization.lua`。
